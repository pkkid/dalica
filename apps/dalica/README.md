# dalica

Dalica desktop app: the eframe window, the control-server transport, the native menu and the rfd picker (`docs/architecture.md` §2). Apps may depend on any crate.

- **Status:** an empty window (M0.8) with its log file (M1.20: `src/logging.rs`, `docs/development.md` §10); the library window comes in M1.18 (`docs/roadmap.md`).
- **OS services** (M15.12, `src/os.rs`, `src/os/`): the real `dalica_engine::os::Os` the window's session uses (headless ones keep the recording fake): Locate on Disk (Explorer `/select,`, `open -R`, Linux's `FileManager1.ShowItems` D-Bus call else the folder opened), the applications that open a file (Linux: desktop entries and `mimeapps.list`; Windows: `reg query` of the type's ProgIDs and open-with lists; macOS: Launch Services), Open With, the external editor (a named program with every file, `open -a`, a Flatpak's forwarding, a desktop entry id; empty: the edit verb or default application) and the clipboard (files, a picture, text). Programs start with an argument vector, never a shell (`security.md` §5.11); setting the default viewer is M15.24's (`src/os/default_viewer.rs`).
- **One Dalica per user** (M15.18, `src/instance.rs`, `src/instance/`, `viewing.md` §3.4): a launch on the per-user library (not `--library`, `--demo`, `DALICA_HOME` or a portable copy) takes an OS lock on `instance.lock` in the library folder, or hands its `--view` file to the Dalica holding it over 127.0.0.1 (port and a 256-bit token in the private `instance.json`; ≤ 64 absolute paths of ≤ 4 KiB, one request within 5 s, refused whole otherwise) and exits 0 once that one's window took it; after 10 s without an answer it starts on its own. The running Dalica brings its window forward and opens the viewer on the file, borderless and full screen; Esc returns the window to where it was. On macOS, Finder's and the Dock's open-documents events open the viewer the same way (`fmv-macos-events`). `cargo test -p dalica --test all instance::` runs the two-process tests.
- **Test it alone:** `cargo test -p dalica` (the logging tests run the test binary and the `dalica` binary as child processes with their settings and temp folders in a temporary directory). `cargo test -p dalica --test all os::` runs the OS services' tests: every OS's argument vectors through a recording runner, fixture desktop entries and `reg query` output, stub programs on `PATH` for this OS, and the clipboard when there is a display (skipped and named otherwise; it puts the text that was there back).
