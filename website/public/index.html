What Dalíca writes to disk

Everything lives next to your photos.

Dalíca never copies your photos into a library of its own. What you add, edits included, goes into one small, readable file per folder, and into the photos' own metadata.

  • Move a folder to another disk and its stars, tags and edits go with it.
  • The index Dalíca keeps for speed is a cache. Delete it and Dalíca rebuilds it from your folders.
  • Originals are only ever moved aside when you Save an edit, never overwritten.

Add a tag in Dalíca and it is written into the photo itself, as XMP dc:subject and IPTC keywords, so any photo app that reads standard metadata sees it. Fields written by other programs are kept exactly as they were.

For scripts and AI agents

Everything is a command.

dalica-cli · control channel

The window and the command line share one engine.

Every action in Dalíca is a named command, 132 of them today. Clicking, pressing a key and running dalica-cli all go through the same code, so whatever you can do by hand, a script can do too, edits included.

  • commands lists every command and its parameters as JSON.
  • run executes one command, or a JSON-lines script from a file or stdin, and answers in JSON.
  • inspect prints the library: folders, photos, stars.
  • snapshot renders the real window to a PNG, with no display or GPU.
  • dalica --control lets a script drive the open window over a local, token-protected socket.
  • New in 0.2: photo.crop.apply, photo.straighten.apply, photo.history.*, edit.zoom.* and more. An MCP server for AI agents follows in 0.5.

Try it on the built-in demo library of generated photos; your own library is never touched. The control protocol →

terminal · dalica-cli
$ dalica-cli inspect --demo | jq .photos
60
$ dalica-cli run --demo - <<'EOF'
{"command":"photo.crop.apply","params":{"id":3,"rect":[0.1,0.1,0.8,0.8]}}
{"command":"photo.straighten.apply","params":{"id":3,"degrees":2}}
{"command":"photo.history.undo","params":{"id":3}}
EOF
{"command":"photo.crop.apply","ok":true,"result":{…"Undo Crop"}}
{"command":"photo.straighten.apply","ok":true,…}
{"command":"photo.history.undo","ok":true,
 "result":{"id":3,"undone":"Straighten"}}
$ echo '{"command":"view.edit","params":{"id":3}}' > edit.jsonl
$ dalica-cli snapshot --demo --script edit.jsonl -o edit.png

Prefer to build it?

Build from source.

Dalíca is pure Rust: no C or C++ libraries to install. You need the Rust toolchain; rustup reads rust-toolchain.toml and fetches Rust 1.98 for you.

Linux
Rust from rustup.rs. To run it, a Wayland or X11 desktop, xkbcommon and a Vulkan driver; most desktops have them (Debian and Ubuntu: libxkbcommon-x11-0 libvulkan1 mesa-vulkan-drivers).
Windows
Rust from rustup with the MSVC toolchain, and the Visual Studio Build Tools (Desktop development with C++) for the linker.
macOS
Rust from rustup and the Xcode Command Line Tools (xcode-select --install).

More in docs/development.md, including how the gates and tests work.

terminal
$ git clone https://github.com/pkkid/dalica
$ cd dalica
# the app, on a demo library of generated photos
$ cargo run --release -p dalica -- --demo
# the app on your own folders, with HEIC photos shown
$ cargo run --release -p dalica --features heif
# the command-line tool: target/release/dalica-cli
$ cargo build --release -p dalica-cli
# contributors: every gate, before each commit
$ cargo xtask ci
