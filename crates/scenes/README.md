# dalica-scenes

**Layer L1.** Procedural test and demo photos (gradients, horizons, soft blobs, text-free patterns) at any size, depth and orientation, with a minimal EXIF block. No media files.

- **May depend on:** `core` (`docs/architecture.md` §2; `cargo xtask layers` enforces it). External: `image` (its JPEG, WebP, GIF and BMP encoders), `png`, `fdeflate` (zlib for Deflate TIFF strips), `zune-jpegxl` (lossless JPEG XL, safe, single-threaded) with `zune-core`, `thiserror`. Tests also use `moxcms`, `tiff` and `jxl-oxide` as independent readers.
- **Public API:**
  - `Scene { seed, width, height, kind }` → `render()` → `Rgb8` (upright). `Kind`: `Gradient`, `Horizon`, `Blobs`. A light square near the top-left marks "up and left". Only `+ − × ÷ √` and a SplitMix64 generator, so pixels and file bytes are identical on every platform and build profile (`tests/scenes.rs` pins golden hashes).
  - `jpeg(scene, quality, Option<&Exif>)`, `png(scene)`. `Exif { orientation, date_time_original, make, model, thumbnail, byte_order }`: the pixels are stored so that the orientation displays them upright; IFD0, the EXIF IFD and an optional IFD1 thumbnail, in `II` or `MM` order.
  - `orient::store` / `orient::display`, `exif::tiff`, `Rgb8::downscale`.
  - `formats` (M5): a scene written in every format Dalica reads, for decoder tests. `tiff(scene, &Tiff)`: our own writer (8/16-bit and float; grey, RGB, CMYK, palette; uncompressed, LZW, Deflate, PackBits; `II` or `MM`; Orientation tag; thumbnail IFD1; ICC tag; rows per strip). `psd(scene, &Psd)`: our own flattened PSD (raw or RLE; 8/16-bit grey, RGB, CMYK, indexed, and 32-bit float grey and RGB; thumbnail 1036 and ICC 1039 resources; CMYK stored inverted as Photoshop does). `webp` (lossless; alpha, EXIF, ICCP), `gif` (1 to 64 frames in a fixed 216-colour palette, so colours survive exactly), `bmp` (RGB, grey, indexed), `jpeg_icc` (APP2 profile, split across segments when large), `jxl` (lossless; grey or RGB, 8/16-bit, alpha at 8 bits only: `zune-jpegxl` 0.5 mislabels 16-bit alpha). `samples(img, colour, depth)` gives the exact stored samples (16-bit values carry a position pattern in the low byte; CMYK is a naive conversion), with `palette`, `quantized` and `alpha` for the rest. No encoder we use writes a CMYK JPEG or a lossy WebP: tests of those use hand-built bytes and the corpus. `image` refuses palette and grey-float TIFFs; `tiff` (its backend) reads grey float but not palette, so the tests relabel a palette TIFF as grey to read its indices.
  - `icc::rgb(space, version)`, `icc::grey(version)`: matrix/TRC profiles built from the published primaries (sRGB, Display P3, Adobe RGB, ProPhoto, Rec. 2020; Bradford-adapted to D50), ICC v2 (`curv` tables, `desc`/`text`) or v4 (`para`, `mluc`, `chad`). They parse with `moxcms` and convert like its built-in profiles (within 2 levels of 255).
  - `demo_library(folders, photos, seed)` → `Vec<DemoFile>` (relative path, bytes, orientation, date, size). This crate never writes to disk (layer rule 4); callers write the files (through `dalica-fs` in the product).
- **Test it alone:** `cargo test -p dalica-scenes` (no window, GPU, network or personal photos needed). The `image` crate also serves as the independent decoder in tests; `tests/formats.rs` reads every M5 format back (`tiff` for layouts `image` refuses, `jxl-oxide` for JPEG XL, structural readers for PSD and ICC) and pins golden hashes of our own writers. Dev builds compile this crate, `image` and `png` at `opt-level = 3` (root `Cargo.toml`), so a 200-photo demo library takes under a second.
