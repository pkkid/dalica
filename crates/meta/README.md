# dalica-meta

**Layer L1.** EXIF / IPTC / XMP reading; write-back of owned fields by segment surgery (merge, never replace); MWG face regions; `.xmp` sidecars for RAW.

- **May depend on:** L0 and `image` (`docs/architecture.md` §2; `cargo xtask layers` enforces it). External: `fdeflate` (compressed PNG text, inflated under a cap), `md5` (the IPTC digest), `log`, `thiserror`.
- **Contract:** `docs/xmp-interop.md` (fields, precedence, containers, ownership); limits in `docs/security.md` §4.2. This crate never touches the disk: it reads and returns bytes, and the caller writes them atomically through `dalica-fs`.
- **Public API (M6.4):**
  - `read(bytes, &Limits) -> Metadata { container, owned, sources, summary, problems }`: `owned` is `OwnedFields { caption, tags, rating, place, date_taken, date_source }` resolved from `sources` (`Sources { exif, iptc, xmp }`) by the precedence rules of `xmp-interop.md` §2 (`Sources::resolve`): caption XMP → IPTC 2:120 → EXIF ImageDescription (camera placeholders such as "OLYMPUS DIGITAL CAMERA" or the make ignored); tags XMP → IPTC 2:25; rating XMP only (`starred()` is rating 5); place EXIF GPS → XMP; date EXIF DateTimeOriginal (with OffsetTimeOriginal and SubSecTimeOriginal) → XMP `exif:DateTimeOriginal` → `photoshop:DateCreated` → `xmp:CreateDate` → IPTC 2:55 + 2:60, else none (the caller uses the file time and flags it). The container walk is strict (`Err`); a damaged block is skipped and listed in `problems`, so a looping EXIF IFD does not hide the IPTC caption beside it.
  - `fields`: `Place` (finite, on the globe), `DateTaken` (local `DateTime`, offset in minutes within ±18:00, the fraction of a second as written; `from_exif`, `parse_iso`), `clean_text` / `clean_tag` / `clean_tags` for tainted text (control characters dropped, trimmed, capped; tags deduplicated case-insensitively, the first spelling kept).
  - `container::scan(bytes, &Limits) -> Scan`: one walker per container (`jpeg`, `png`, `webp`, `tiff`) with the payloads (`exif`, `xmp`, `extended_xmp`, `photoshop`, `iptc`, `texts`) and the byte `Span` of every metadata block (`BlockKind`, `rewritable`). JPEG: APP1 EXIF and XMP, extended-XMP chunks reassembled by the GUID the main packet declares (all chunks agreeing on the length, inside it, covering it, standard + extended ≤ 16 MiB, the GUID the MD5 of the packet, `jpeg::extended_guid`; otherwise refused as a problem), APP2 ICC and MPF, APP13 Photoshop resources (split segments joined), COM. PNG: `eXIf`, XMP in `iTXt`/`tEXt`/`zTXt`, "Raw profile type" EXIF/IPTC/8BIM/XMP text (an `iptc` or `8bim` profile holds Photoshop resources or a bare IIM stream, the form ImageMagick writes, told apart by `iptc::read::is_iim`; the first one is read, every later one holding readable IPTC is rewritable too), `iCCP`, other text for the listing. WebP: `EXIF`, `XMP `, `ICCP`; the RIFF header and `VP8X` are rewritable structure. TIFF: IFD0 tags 700, 33723, 34377 (resources, or a bare IIM stream from ImageMagick), 34675; the header pointer and IFD0 are rewritable (append-only writes), the EXIF and GPS IFDs reported. `payload` / `payload_digest`: the bytes outside the rewritable spans.
  - `exif::read::{read, walk}` through `dalica_image::ifd` (≤ 1,024 IFDs, depth ≤ 10, ≤ 8,192 entries, loops and out-of-range values are `Err`; zero denominators and impossible dates are left out); `exif::Summary` (camera, lens, exposure, aperture, ISO, focal length, flash, orientation, colour space, date digitized; `rows()` in the Properties order of `ui-layout.md` §7); `exif::tag_name`.
  - `iptc::read::{resources, datasets, read, Charset}`: 8BIM resources and IIM datasets (extended lengths), each length inside its block, a dataset ≤ 64 KiB, ≤ 10,000 datasets, ≤ 4,096 resources; text UTF-8 when 1:90 says so, else UTF-8 if valid, else Latin-1.
  - `iptc::write::{write_stream, write_resources, digest}` (M6.10): `IptcEdit { caption, keywords }` (`IptcEdit::of(&Changes)`) merged into an IIM stream or a block of Photoshop resources: 1:90 = UTF-8, 2:120 in the first old one's place, one 2:25 per tag in the first old keyword's place, missing datasets in dataset order, every other dataset and resource byte for byte (record-2 Latin-1 text re-encoded to UTF-8 so it reads the same under the new declaration), the digest resource 0x0425 set to the MD5 of the new stream. A caption past 2,000 bytes or a keyword past 64 is cut at a character boundary (`Written::truncated`, one log line).
  - `exif::edit::edit(block, &ExifEdit, max_len, &Limits)` (M6.10): `ExifEdit { caption, date_taken, place }` (`ExifEdit::of(&Changes)`) written in place or appended, never repacked: a value the entry already holds left where it is, a value no larger than the old one where it was, a larger or new one appended (word aligned) with only its offset changed, an IFD that gains entries appended with only its pointer changed; maker notes, thumbnails and foreign tags keep their bytes and offsets; replaced or removed owned values zeroed when nothing else shares them. Dates set DateTimeOriginal and DateTimeDigitized with OffsetTime/SubSecTime (removed when absent); places write DMS rationals and refs (GPSVersionID 2.3.0.0 added to a new GPS IFD); removing a place deletes the four latitude/longitude tags only; an ImageDescription that is a caption follows the caption. No block and nothing that needs one: `Ok(None)`. Past `max_len` (`MAX_JPEG_EXIF` for one APP1): `Err(TooMany("EXIF bytes for the <field>"))`.
  - `xmp` (M6.9): `xml` is our own bounded tokenizer (no `DOCTYPE` or entities, depth ≤ `MAX_DEPTH` 64, ≤ `MAX_NODES` 200,000) keeping the byte span of every element and attribute; `read(packet, extended, &Limits) -> XmpOwned` reads `dc:description` (`x-default`, else an item without a language), `dc:subject`, `xmp:Rating`, `exif:GPSLatitude`/`GPSLongitude`, `exif:DateTimeOriginal`, `photoshop:DateCreated` and `xmp:CreateDate` in attribute and element form, matching namespaces by name, the extended packet filling what the standard one lacks; `rows` lists every property (arrays joined, other languages as `[lang]`, structures as `a/b`, items as `a[1]`). `merge(packet, &Changes, metadata_date, &Limits) -> Option<Merged>`: the changed owned properties cut from every other top-level description (attribute or element form, the rest of it byte for byte), Dalica's description (the one holding only owned properties and `xmp:MetadataDate`) rewritten in place or added before `</rdf:RDF>`, other languages of `dc:description` kept, clearing removes, the place into an existing packet and the date mirrors only where present (a new packet, started only for a caption, tags or a rating, takes the place and `exif:DateTimeOriginal` too), text escaped and non-XML characters dropped, the padding absorbing the change in size, a new packet (2 KiB padding) when there is none, `None` when nothing changes; `Merged::{len, min_len, fit}` for the APP1 limit (`JPEG_MAX_PACKET`). Every merged packet is parsed again and its changed properties checked.
  - `listing(bytes, &Limits) -> Listing { rows: Vec<Row { group, label, value }>, truncated }`: Show All Metadata. EXIF by IFD with tag names, IPTC by dataset name, XMP (M6.9), text chunks and comments, then unreadable blocks; ≤ 10,000 rows, values ≤ 1,024 characters, control characters as spaces and bidirectional controls shown as `<U+…>`.
  - `write_owned(bytes, &Changes, &WriteOptions) -> Result<Vec<u8>>`: the one write entry point. `Changes { caption, tags, star, place, date_taken }` filtered by `WriteOptions { captions_tags_places, stars_as_ratings, dates, limits }` (defaults on, off, on); nothing to change returns the bytes; a file whose EXIF, XMP or IPTC is unreadable is not rewritten; a TIFF-structured raw is never written. The per-container writers in `write/`: `png` (M6.18: XMP in an uncompressed `iTXt` where the old XMP chunk stood; EXIF back into `eXIf` or the raw profile that held it; IPTC only into an existing raw profile, every IPTC-holding copy rewritten in its own form (bare IIM or resources) so no old caption lingers; new chunks before the first `IDAT`; CRCs recomputed), `webp` (M6.18: `EXIF` and `XMP ` replaced in place or added after the image data, the `VP8X` flags set, a simple-format file promoted to `VP8X` with the canvas size and alpha hint of its `VP8 `/`VP8L` header, the RIFF size fixed), `tiff` (M6.18: tags 700, 33723 and 34377 and the caption's ImageDescription copy by the append-only rule: values in place when they fit, else appended word aligned with the old bytes zeroed; IFD0 in place unless it grows, else appended with only the header offset changed; a file whose IFD0 or rewritten values share bytes with any other IFD, value, strip or tile is refused; place and date only through the XMP mirrors, a place or date no mirror can take refused up front as `Error::Refused { field, why }`); `jpeg` (M6.17: only the first APP1 EXIF, the first APP1 XMP and the APP13 Photoshop segments are rewritten, through `exif::edit`, `xmp::merge::merge_at` fitted to one APP1 by dropping padding only, and `iptc::write::write_resources`, IPTC written whenever the caption or tags change except a removal into a file without IPTC, APP13 rejoined and split at the segment limit; new segments after SOI and APP0 (EXIF, then XMP) and after the leading APP0–APP12 run (APP13); a block that already holds the values is left alone, so writing twice gives the same bytes; past one APP1 the write fails naming the field). `WriteOptions::metadata_date` is the time of the write for `xmp:MetadataDate`, set by the caller from the session's clock (`None`: Dalica's description keeps its date, a new one gets none). A new XMP packet (started only for a caption, tags or a rating) gets the place and the date (`exif:DateTimeOriginal`) in the same merge (`xmp::merge::merge_at`). `verify(before, after, &Changes, &Limits)`, run on every write: same container, reads back cleanly, every byte outside the rewritable spans unchanged (TIFF: every such byte of the old file still at its offset), each changed field re-read equal (a place within 1e-6°; unstarring keeps a rating Dalica did not set); the error names the field, never its value.
  - `xmp_sidecar` (M6.19, `xmp-interop.md` §7): `.xmp` sidecars for RAW files. `Sidecars::new(names, is_raw)` indexes one folder listing (this crate reads no directory): `get(raw) -> SidecarName { existing, write }` (`<stem>.xmp`, then `<stem>.XMP` in any case, then `<file>.xmp` / `<file>.XMP`; an existing sidecar is written back under its own name, else `<stem>.xmp`; the stem's sidecar of a RAW+JPEG pair is the RAW's; RAWs sharing a stem: the one named exactly the stem gets it, the others `<file>.xmp`; names compared without case) and `owner(sidecar)`. `read(raw, sidecar, &Limits) -> RawMetadata { metadata, xmp_from, damaged }`: the RAW's own metadata (a TIFF-structured RAW's EXIF, IPTC and embedded XMP) with the sidecar's XMP in place of the embedded packet; a damaged sidecar is reported and the embedded packet read instead. `merge(raw, sidecar, &Changes, &WriteOptions) -> SidecarWrite::{Unchanged, Write(bytes), ReplaceDamaged { bytes, damaged }}`: an existing sidecar through `xmp::merge` (develop settings, history, other namespaces, the packet wrapper and its padding byte for byte); a new one starts from the RAW's embedded packet, else a plain `x:xmpmeta` document seeded with Dalica's description (so the date mirror is written too); the result is checked by `well_formed(bytes, &Limits)` (UTF-8 within `max_xmp`, the tokenizer's limits, an `rdf:RDF` with content).
  - `carry` (M8.7, `data-model.md` §6): metadata carried to a new file. `carry(source, target, &Carry { width, height, thumbnail, remove_location, changes, options }) -> Carried { bytes, thumbnail, dropped }`: the target (the JPEG or PNG the encoder wrote, with its own ICC profile) takes the source's metadata (JPEG, PNG, WebP or TIFF, raws included) as it applies to the new pixels. EXIF (`carry::exif`): Orientation 1, PixelX/YDimension the new size (ImageWidth/ImageLength too where IFD0 has them), ColorSpace sRGB, an interoperability index other than `R98` set to `R98`, IFD1 replaced by the given JPEG thumbnail or dropped (left out, `thumbnail: false`, when it would pass one APP1); the image-structure tags, the DNG tags and the XMP/IPTC/Photoshop/ICC tags of IFD0 left out; edited in place or appended, never repacked, so maker notes keep their offsets; a whole TIFF file stays in place when it has a maker note and its metadata fits 64 KB, else its kept tables and values are packed (pixels never copied) and a maker note that is an IFD with TIFF-header offsets inside it has them moved; a source without EXIF gets a minimal block. XMP (`carry::xmp`): `tiff:Orientation` 1, `tiff:ImageWidth`/`ImageLength`, `exif:PixelX/YDimension` and `exif:ColorSpace` set where the packet states them (never added), the padding absorbing the change; extended XMP into a JPEG unchanged (left out of a PNG and when removing the location finds GPS in it, listed in `dropped`). IPTC (`carry::iptc`): datasets byte for byte, as APP13 Photoshop resources in a JPEG (a bare IIM wrapped with its digest; resources 0x0406, 0x0409, 0x040C, 0x040F, 0x0422–0x0424 left out) and a "Raw profile type iptc" `tEXt` chunk in a PNG. `remove_location`: the EXIF GPS IFD and every `exif:GPS*` property gone, place names kept, a place among `changes` not written. The target's own metadata blocks are replaced, everything else kept byte for byte; then `write_owned` merges `changes` under `options` and the result is checked (reads back, orientation 1 and the size in EXIF and XMP, no GPS when removed). An unreadable source EXIF, XMP or IPTC is `Err`. `set_orientation(jpeg, orientation, &Limits)`: the lossless fallback of a rotate-only Save, JPEG only: IFD0's Orientation value written in its entry (or IFD0 appended with it, or a new EXIF block after APP0), `tiff:Orientation` following where the XMP has it, every other byte kept and checked by `verify`; an orientation outside 1–8 is `Error::Refused`.
  - `Limits` (`docs/security.md` §4.2, passed explicitly), `Error`, `Problem`. A write that fails is `Error::Verify` when a written file failed its check, and `Error::Refused { field, why }` when a field was refused before anything was written (its message, "the place cannot be written: …", is what the notice shows).
- **Test it alone:** `cargo test -p dalica-meta` (no window, GPU, network or personal photos needed). `tests/build/` builds every test file from the specifications (EXIF/TIFF structures in either byte order, IIM streams, Photoshop resources, XMP packets, JPEG, PNG, WebP and TIFF containers). `tests/read.rs`: each field from each source in each container, the precedence rules, IPTC Latin-1 and UTF-8, placeholders, extended XMP (reassembled; oversized, mismatched, gapped or undeclared refused), the listing and its bounds, IFD loops, out-of-range offsets and huge counts, every limit at its boundary, truncation at every byte, every single-byte flip, proptest random bytes and mutations, the write skeleton and its verification. `tests/iptc_write.rs`: 1:90, digests, Latin-1 legacy streams, truncation at the IPTC limits, foreign datasets and resources byte for byte, idempotence, hostile input. `tests/write_png_webp_tiff.rs`: every owned field written and read back in each of PNG, WebP and TIFF, foreign chunks, tags, strips and maker notes byte for byte and in place, real images that decode to the same pixels after a write (hand-built lossless and lossy WebP, PNG, TIFF), simple WebP promotion, idempotence, IPTC 1:90 and digests, the TIFF in-place/append rules and refusals, truncation, byte flips and proptest. `tests/exif_edit.rs`: dates with offsets and sub-seconds, southern/western places in both byte orders, removing a place, the caption copy, a maker note with absolute offsets that reads the same after every edit, the APP1 limit, idempotence, hostile input. `tests/write_jpeg.rs`: every owned field through EXIF, XMP and IPTC in each kind of JPEG, foreign segments and the data inside the rewritten blocks byte for byte (maker note, thumbnail, extended XMP, other descriptions, datasets and resources), the payload digest, identical decoded pixels (a real baseline JPEG built in the test), idempotence, the rating rule, IPTC 1:90 and digest, the APP1 limits naming the field, where new segments go, APP13 over several segments, truncation at every byte, proptest random bytes, mutations and captions. `tests/xmp.rs` and `tests/xmp_merge.rs`: the XML tokenizer's limits (entities and `DOCTYPE` refused, depth and node counts at and past their limits), reading the owned properties in every RDF form, and the merge writer (foreign descriptions and properties byte for byte, other languages kept, the rating rule, padding, idempotence). `tests/carry.rs`: a JPEG, a TIFF and a WebP source in both byte orders into a JPEG and a PNG target (orientation 1 and the new size in EXIF and XMP, foreign EXIF, XMP, IPTC and resources byte for byte, a maker note with absolute offsets in place and packed, GPS removed or kept, the owned fields merged, the thumbnail replaced, dropped or left out), `set_orientation` changing one byte, hostile blocks, truncation at every byte, byte flips and proptest. `tests/xmp_sidecar.rs`: name resolution (every accepted form and their order, RAW+JPEG pairs, RAWs sharing a stem, names differing by case, 150,000 names, a property test over random folders), develop settings and history byte for byte, a new sidecar from a DNG's packet or a plain one, damaged sidecars reported and replaced, truncation, byte flips and proptest.
- **Corpus test:** `tests/corpus.rs`, behind the `corpus` feature and run by `cargo xtask test-corpus -p dalica-meta` (`docs/development.md` §11): every file of the pinned `metadata` set (our own `dalica-scenes` photos after exiv2, ImageMagick and Pillow wrote captions, keywords, ratings, GPS, dates, face regions and foreign metadata, and RAW `.xmp` sidecars) reads without a problem, and every owned field written into it passes `verify`, keeps every byte outside the rewritable spans and every foreign listing row, leaves the other owned fields alone and writes again to the same bytes; RAW refusals (`Error::Unsupported`) and TIFF place/date refusals (`Error::Refused` naming the place or the date taken) are counted, not failed. The counts must reach `tests/corpus_floors.json`, which only rise.
- **Fuzz it:** `crates/meta/fuzz` is a separate cargo-fuzz workspace (nightly, excluded from the root workspace) with the targets of `security.md` §7.1: `exif` (an EXIF structure alone and inside JPEG, PNG and WebP), `xmp` (the XMP entry points, the merge writer, extended-XMP reassembly with MD5 GUIDs, and that file written through `write_owned`), `iptc` (resources and datasets alone, in APP13 and in TIFF tag 33723), `write_merge` (parse → `write_owned` → re-parse: a returned write always passes its verification, reads back, and writing it again gives the same bytes), `carry` (any file as the source of a JPEG or PNG copy: a returned copy reads back upright and without GPS when removed; `set_orientation` passes its verification and reads back). `cd crates/meta/fuzz && cargo +nightly fuzz run exif`; the Fuzz workflow builds them on pull requests that touch this crate and runs them all when dispatched by hand.
