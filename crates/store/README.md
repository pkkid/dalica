# dalica-store

**Layer L3.** Persistence of the model: index journal + snapshot, model ↔ sidecar mapping, the debounced sidecar writer, the metadata write queue, rebuild from folders.

- **May depend on:** L0–L2 (`docs/architecture.md` §2; `cargo xtask layers` enforces it): `core`, `fs`, `sidecar`, `library`, and for the metadata write queue `meta` and `image` (format sniffing). External: `serde`, `serde_json`, `thiserror`.
- **Public API (M1.9):**
  - `Store::open(library_dir, now)` → `Opened { store, library, report }`: loads `index.snap` and replays `index.log` after it. Damage never fails the open: a torn or bad tail is cut off (`JournalTail`); a damaged snapshot is kept aside and the journal used when it holds every op (`SnapshotSetAside`); a journal behind its snapshot restarts (`JournalReset`); otherwise the index is kept aside as `.corrupt-<time>` and the library opens empty (`RebuildNeeded`).
  - `Store::append(&Op)` (synced, ≤ 16 MiB per record), `snapshot(&Library)` (atomic, then a fresh journal), `wants_snapshot()`, `seq()`.
  - `journal` (`<crc32> <json>` lines, header `{"journal": 1, "base": N}`), `snapshot` (one checksummed record), `crc32`.
- **Public API (M1.10):**
  - `mapping`: `PHOTO_FIELDS` (every `Photo` field: index, file or sidecar), `PHOTO_DATA` (per-photo data kept beside `Photo`: the sketch, index only; M6.8 adds the info and the synced hashes, below), `folder_state`, `apply`, `star_of`.
  - `write_folder(&FolderState, now)`: re-read, merge, skip if unchanged, atomic replace with an identity check; a damaged sidecar is kept as `.dalica.json.corrupt-<time>`. Any thread but the UI thread.
  - `SidecarWriter`: `mark_dirty`, `write_due` / `write_due_with` (at most once per second per folder on the clock), `flush` / `flush_with` (everything now), `pending` (folders still to write), `read_only` folders after damage, `clear_read_only`.
  - `import_sidecars(&Library, now)` → `Import { ops, read_only, problems }`: after a rebuild from the folders, the ops that bring back the sidecars' user data (M6.8: one `SetStars`, `SetPhotoInfo` and `SetFolderInfo`).
- **M6 fields (M6.8, `mapping`, `data-model.md` §3):**
  - Tables of every model field and where it lives (`Source::Index`, `File`, `Sidecar(key)` under `photos.<name>`, `FolderSidecar(key)` under `"folder"`, `Fields(table)`): `PHOTO_FIELDS`, `PHOTO_DATA` (sketch, info, synced), `PHOTO_INFO_FIELDS` (caption, tags, hidden, edits, redo, date), `SYNCED_FIELDS` (all index-only), `FOLDER_FIELDS`, `FOLDER_DATA`, `FOLDER_INFO_FIELDS` (description, date, place, hidden). `tests/sidecars.rs` destructures each struct, so a new field must be placed.
  - `FolderState { id, path, folder: FolderInfo, photos: Vec<(name, PhotoState { star, info })> }` from `folder_state`.
  - `read_photo(&Sidecar, name) -> PhotoReading` and `read_folder(&Sidecar) -> FolderReading`: one `Reading` per key, `Usable(value)` (the empty value when absent) or `Unusable` (wrong type, or a recipe past the library's caps: kept in the file, not used); text past its cap is cut for the model and kept whole in the file, tags are cleaned; `notes` say what was over a cap. `merged(&own)` gives the model's value, keeping `own`'s where the reading is unusable.
  - `apply(&FolderState, &mut Sidecar)` writes only the keys whose value differs from what the file reads as (so equal content in another spelling keeps its bytes), writes over an unusable value only when the model holds a value of its own, and returns the places it refused (a `photos`, entry or `"folder"` that is not an object). `star_of` is kept.
  - The snapshot keeps `photoInfo`, `folderInfo` and `synced` lists (left out when empty; version 1); the journal records M6's ops like any other. The synced hashes never reach a sidecar and start empty after a rebuild.
- **M8 fields (M8.9, `mapping`, `rebuild`, `snapshot`, `data-model.md` §3, §6):**
  - Tables: `PHOTO_DATA_M8` (`saved` → `SAVED_FIELDS`, each `Source::Originals(key)` in the originals record; `savedAs` → `SAVED_AS_FIELDS`, one object under the photo's `savedAs`) and `FOLDER_DATA_M8` (`project` in `"folder"`). `tests/m8_fields.rs` destructures `Saved` and `SavedAs` and checks the keys against `dalica-sidecar`'s.
  - `PhotoState { star, info, saved_as }`, `FolderState { …, project }`, `photo_state(&Library, &Photo)`; `PhotoReading::saved_as` (unusable when the name is not one plain path component or the recipe is past the caps) and `FolderReading::project` (an unknown kind is unusable); `apply` writes both under the M6 rules; `project_text`.
  - The originals record: `read_originals(&Originals) -> OriginalsReading { saved, notes }` (plain names, readable entries, digest ≤ 256 bytes and recipe within the caps), `saved_of(Entry) -> Saved`, `originals_entry(&Saved) -> Entry` (what a Save writes).
  - `rebuild::read_originals(folder, now) -> OriginalsFile::{Absent, Read, Unreadable, SetAside { why, kept }}` (never through a link; a damaged record kept as `.dalica.json.corrupt-<time>`), `originals_path(folder)`; `import_sidecars` adds `SetSavedAs`, `SetProjects` and a derived `SetSaved` (an absent record clears the folder's records, an unreadable one changes none; a folder without a sidecar still has its record read).
  - The snapshot keeps `saved`, `savedAs` and `projects` lists (left out when empty; version 1). `stale` counts `savedAs` as Dalica's data.
- **M9 (M9.6 albums and fields, M9.9 carry and the file-operation journal; `data-model.md` §3, §4, §8):**
  - Albums and M9's fields: `mapping` tables `PHOTO_DATA_M9` (`albums` memberships in the sidecar; search facts, content digest and times index-only), `FOLDER_DATA_M9` (`sort`/`reverse` in `"folder"`, the album names at the top level), `LIBRARY_DATA_M9` and `ALBUM_INFO_FIELDS`; `PhotoState::albums`, `FolderState { sort, album_names, known_albums }`, `read_album_names`. `albums` reads and writes `albums.json` (`read`, `reading`, `state`, `merged`, `write`; a damaged file set aside), and `rebuild::import_library` brings albums back from it and from the folders. `stale` counts `albums` as Dalica's data.
  - `carry`: `entries(&Carry, now)` carries photo entries (unknown keys, memberships and the album names they need) between two folders' sidecars, or renames them in one, merged entry by entry and never replacing a sidecar, the destination written first; `backups(&Carry, now)` moves or copies the originals backups through `dalica-fs` and carries their record entries. `Carried { carried, merged, absent, refused }`; `CarryError::{Missing, ReadOnly, SetAside, Fs, SourceKept}`. `SidecarWriter::carry(&Carry, from, to, state_of, now) -> CarryReport` runs `entries` in order with the writer: the folders' pending writes, the carry, then the destination again from the model.
  - `intents`: the journal `file-ops.json` (`Intents::open` / `begin` / `item` / `retarget` / `end` / `flush` / `next_id`; a damaged file set aside with its readable operations kept, `Problem::SetAside`) and `plan(&Intent, &[Facts]) -> Vec<Decision>` (`Action::{Back, Forward { finish, carry }, Wait, Lost}`), pure.
- **Sketches (M4.2):** the colour sketch is derived data (`data-model.md` §4): `Op::SetSketches` is journalled like any op, the snapshot keeps a `sketches` list of `[photo id, base64]` pairs (left out when empty, so older snapshots still read), a rebuild starts without sketches, and no sketch ever reaches a sidecar (`PHOTO_DATA`).
- **Offline folders (M5.13, `data-model.md` §7, `security.md` §5.9):** a folder that is not there (its volume unplugged or its share unreachable, or it was renamed or removed) is never created to write into: the write fails (`Outcome::Failed`, so the edit is reported unsaved), the folder stays dirty and waits (`waiting()`), and it is looked at again when marked dirty (the engine does so when its root comes back) or after `WAIT_RETRY` (10 s), not every second. A folder that left the model while waiting is dropped (the engine reports it, M5.20). Folders under a held root (`hold(roots)`, the engine's offline roots, M5.17) are never written even though they exist, and are reported unsaved like a missing one. **Per-write root check (M6.43):** `guard(Vec<(root, RootCheck)>)` hands the writer a check per watched root (`RootCheck`, a closure the engine builds from its root probe); before writing a folder under a guarded root the writer runs it (at most once per root per pass; a panicking check fails), and a failed check is treated like a missing folder: `Outcome::Failed` ("… is not the volume the library knows …"), nothing written, the folder dirty and waiting. `tests/offline.rs` covers it.
- **Stale entries (M5.17, `stale`):** a photo deleted outside Dalica leaves the library at once; its sidecar entry (Dalica's own data: a star, any M6 field, M6.8, or `savedAs`, M8.9; a plain name, not in the model, file absent) is marked `dalica.missing` with the time and pruned on the folder's next sidecar write after 30 days; other programs' entries are never touched. The engine keeps the list of waiting folders across restarts (`dalica-engine`'s `offline` module).
- **The metadata write queue (M6.30, `metawrite`, `data-model.md` §5, `xmp-interop.md` §1, §5, §7):**
  - `MetaWriteQueue`: `enqueue(Request, now)` (batched per photo: fields add up, the latest values win; due after `DEBOUNCE`, 1 s of quiet), `due(now)`, `write(photo, &Options, now)` (one photo now, for the engine's job: progress and Cancel), `write_due`, `flush`, `remove`, `pending`, `waiting`, `hold(roots)` / `guard(roots)` (offline roots wait and are written on return, M5.13/M6.43), `note_synced` (a scan set the synced hashes). It remembers the synced hashes it produced until a request carries them, so an undo queued before the model caught up is written, not imported.
  - `write_file(&Request, &Options, now)`: one write, any thread but the UI thread: `fs::stat` + `fs::read` (identity, times, read-only), `meta::read`, the per-field decision of `dalica_library::sync` (write / import / keep / both changed), `meta::write_owned` (merge + verify), `fs::replace` expecting the identity read (a file changed since is re-queued and read again), `fs::set_times` with the old time unless `update_modification_time`, the new synced hashes. A RAW (sniffed from its content) gets its `.xmp` sidecar only with `raw_xmp_sidecars` (`meta::xmp_sidecar`; a damaged one kept aside as `<name>.xmp.corrupt-<time>`); GIF, BMP, HEIC, video … are `Skipped`, read-only files `Failed`, both with the reason (the folder sidecar keeps the values); a disk error is tried `MAX_TRIES` (3) times.
  - `FileResult { status: Written(path) | Unchanged | Skipped | Failed | Waiting | Requeued | Gone, fields: [(Field, Written | Unchanged | Imported | Conflict { written } | Skipped | Failed)], file (the file's values, for imports and conflicts), synced, set_aside, note }`: what the engine turns into import ops, `SetSynced`, Properties' conflict line and toasts (M6.33). The queue reads no clock: `now` is the session's.
- **Test it alone:** `cargo test -p dalica-store` (no window, GPU, network or personal photos needed): replay reproduces the model, every byte-prefix of a journal replays to its last complete op (read in memory; opened at the record boundaries, and at every byte at full strength), damaged records, snapshots and versions recover as reported. `tests/sidecars.rs`: stars reach the sidecar with other keys intact, writes are debounced on virtual time, a fault of each kind leaves the old or the new sidecar (`fs` tries every point). `tests/fields.rs`: every field of M6, M8 and M9 at once through §10.1 (delete the index, rebuild from the sidecars, the originals records and `albums.json`, compare), journal replay and snapshots, clearing, and an entry holding only Dalica's fields marked and pruned like a starred one. `tests/sketch.rs`: sketches survive journal replay and snapshots, a torn tail loses only the torn batch, none reaches a sidecar, the index growth for 100 k sketches (2 000 in a task's gate). `tests/m6_fields.rs` (M6.8): §10.4, §10.7 names with every field, wrong types kept and reported once, equal content in another spelling left alone, a proptest mapping round trip. `tests/m8_fields.rs` (M8.9): every M8 field mapped, hostile names and wrong types kept and never used, a damaged record set aside and reported, proptest round trips. `tests/m9_fields.rs`: every M9 field mapped, a sort Dalica cannot hold kept, hostile values never panic. `tests/offline.rs`: a volume "unplugged" by renaming its root gets no folder created, its write waits (not retried at the debounce) and lands once the root is back, with the earlier entries kept. `tests/carry.rs` (M9.9): a moved photo arrives with its unknown keys, memberships and album names and leaves the source; a star in the debounce lands in the destination in either order; renames, duplicates renamed on the way, copies and folder merges; backups and records travel and copies duplicate them; a fault of each kind in either write keeps the entry and a second carry finishes; damaged and missing folders. `tests/intents.rs` (M9.9): the journal round-trips, batches large operations, a failed write enters nothing, `plan` answers every kind × state × fact, hostile journals (random bytes and operations, deep nesting, past the size limit) never panic and are set aside. `tests/metawrite.rs` (M6.30): fields reach JPEG and PNG files with the pixels and the time kept, batching and debounce, `xmp-interop.md` §8 test 8 (first-scan import, the sidecar wins, a change made elsewhere imported, both changed reported, the rebuild fallback) and test 9 (an error or a crash at a step of the replace, one of each kind, leaves the old or the new file, and the next pass restores the time), offline roots, read-only files with the sidecar intact, formats that cannot be written, a file changed between read and write, RAW `.xmp` sidecars. The integration tests are one binary (`tests/all.rs`, one module per file: `cargo test -p dalica-store --test all <file>::` runs one); a task's gate runs them quick, `DALICA_FULL_TESTS=1` at full strength (every property case, every size).
