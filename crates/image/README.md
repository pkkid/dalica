# dalica-image

**Layer L1.** Sniffing, scaled decoding, encoding, orientation, ICC → sRGB, decode limits, embedded thumbnails and RAW previews (a bounded TIFF/IFD walker of our own).

- **May depend on:** `core` (`docs/architecture.md` §2; `cargo xtask layers` enforces it). External: `zune-jpeg`, `png`, `tiff`, `image` (GIF, BMP), `image-webp`, `jxl-oxide` (and its `jxl-bitstream`, `jxl-coding`, `jxl-oxide-common`), `heic-rs` (only with `heif`), `moxcms`, `log`, `thiserror`.
- **Public API (M1.5):**
  - `sniff(bytes) -> Option<Format>`: the format from magic numbers, never the file name (JPEG, PNG, TIFF/RAW, WebP, GIF, BMP, HEIF, AVIF, JPEG XL, PSD; `Format::supported()` is JPEG and PNG in M1).
  - `read_header(bytes, &Limits)` / `read_header_file(path, &Limits)` → `Header { format, width, height, orientation, exif, exif_error, thumbnail }`: size from the JPEG frame header or PNG IHDR, EXIF from JPEG APP1 or PNG `eXIf`, without decoding. A bad EXIF block leaves the photo upright as stored, with the reason in `exif_error`. `Header::thumbnail(file)` gives the embedded JPEG thumbnail's bytes.
  - `ifd`: the bounded TIFF/IFD reader (`Tiff`, `Ifd`, `Entry`, `Visited`): ranges checked before reading, loop detection, caps on IFDs, depth and entries. `exif::read`: orientation, DateTimeOriginal, DateTimeDigitized, make, model, the IFD1 thumbnail range (strict: any loop or bad offset is an `Err`).
  - `orient`: `Orientation` (1–8, `display_size`), `apply(Rgba8, Orientation)`.
  - `Limits` (`security.md` §4.2), `Rgba8`, `Error`.
- **Public API (M1.6):**
  - `decode(bytes, &Limits)` → upright `Rgba8` (sRGB assumed until M5); `decode_thumbnail(bytes, long_side, &Limits)` decodes and fits (no DCT scaling in `zune-jpeg` 0.5), and past 64 MP uses the embedded EXIF thumbnail or refuses. The declared size is checked before any decoder is created.
  - `resize::fit` / `resize::resize`: exact area average in integer arithmetic, identical on every CPU.
- **Public API (M5.1):**
  - `formats/`: one module per format (`jpeg`, `png`, `tiff`, `webp`, `gif`, `bmp`, `jxl`, `psd`, `heif`, `bmff`, and `raw/` with `tiff_based`, `cr3`, `raf`, `crw`, `mrw`, `x3f`), each with `header`, `decode`, `embedded_thumbnail`, `DECODES` and `REASON` (the contract is in `formats/mod.rs`); `formats::{header, decoder, embedded_thumbnail, decodes, reason}` dispatch by `Format`. At M5.1 only JPEG and PNG decoded and the rest were stubs answering `Unsupported`; M5.6–M5.10 filled them (below).
  - `Format::Raw(RawKind)`, `Format::ALL`, `Format::name()`; `sniff` tells the RAW containers apart by content (each `raw/*` module's `recognise`), TIFF-structured raws by a bounded IFD walk when the bytes hold IFD0.
  - `Decoded` (8/16-bit or float samples; `ColorModel` grey, RGB or CMYK ink; alpha; ICC bytes; orientation), `DecodeOptions { color_managed }`, `decode_with`, `decode_thumbnail_with`, `decode_as(format, …)` (no sniffing).
  - `color`: the one colour stage to 8-bit sRGB (`to_srgb8`, `load_profile`, `ColorPath`): ICC v2/v4 through `moxcms`, untagged = sRGB, an unusable profile logged and shown as sRGB, CMYK without a profile converted naively.
  - `Budget` (every pixel buffer charged to `max_alloc` and reserved fallibly), `Work` (step counters on our container walks), `Limits::{max_icc, max_icc_tags}`; `Error::Panic` (a third-party decoder's panic, caught) and `Error::reason()` (the tile text).
- **Public API (M5.6):** `formats::tiff` decodes TIFF through the pinned `tiff` decoder after our own IFD walk has checked the page's layout and charged its memory: 1–32-bit integers and 16/32/64-bit floats; grey, RGB, CMYK ink and palette; chunky or planar; strips or tiles; None/LZW/Deflate/PackBits/JPEG; alpha from ExtraSamples; the ICC tag; multi-page files show their first full-resolution page. `formats::tiff::thumbnail(bytes, long_side, &options, &limits)` decodes the smallest reduced-resolution page covering the target (`decode_thumbnail` uses it first); `MAX_CHUNKS` caps strips and tiles at 2²².
- **Public API (M5.7):** `formats::webp` (our own RIFF walk; lossy, lossless, alpha, an animation's first frame through `image-webp`; EXIF orientation and thumbnail, ICCP; `MAX_FRAMES` = 10,000), `formats::gif` (our own block walk to the first frame, decoded through `image`'s GIF decoder on the logical screen) and `formats::bmp` (core to V5 and OS/2 headers, a V5 header's embedded profile, through `image`'s BMP decoder).
- **Public API (M5.8):** `formats::jxl` through `jxl-oxide` (single-threaded; its allocation tracker lent what the decode's `Budget` has left; upright; 8/16-bit or float, grey or RGB, alpha; the embedded or enumerated colour encoding to the colour stage; since M6.41 an embedded profile's declared sizes are read first with `jxl-bitstream`, `jxl-coding` and `jxl-oxide-common`, refused past `max_icc` and otherwise charged, and the embedded profile itself goes to the colour stage) and `formats::psd`, our own reader of PSD/PSB merged composites (raw and PackBits; 8/16/32-bit grey, RGB, CMYK, indexed, bitmap, duotone; thumbnail resource 1036 as the embedded thumbnail, ICC resource 1039).
- **Public API (M5.9):** `formats::raw::tiff_based` shows DNG, CR2, NEF, ARW, PEF, ORF, RW2 and SRW through their largest embedded JPEG preview (IFD chain, SubIFDs, EXIF IFD, JPEG strips, RW2's JPEG tag, maker-note pointers), orientation from IFD0, Adobe RGB/ProPhoto previews converted. `ifd::Tiff` gains `new_raw` (ORF and RW2 headers), `headerless`, `rebased`, `walk`, `value_range`, `uints`, `data`, `is_little_endian`; `exif` gains `read_tiff`, `ColorSpace`, `StripThumbnail`, `strip_image`, `decode_strip` and `strip_thumbnail_rgba` (uncompressed IFD1 strip thumbnails, the fast path's fallback past 64 MP).
- **Public API (M5.10):**
  - `formats::bmff`: the bounded ISOBMFF box walk (`Boxes`, `BoxRef`, `child`, `path`; nesting ≤ 12, ≤ 4,096 boxes per level, every box counted) and the `ftyp` brands.
  - `formats::raw::{cr3, raf, crw, mrw, x3f}` show the largest embedded JPEG and offer the next smaller one as the thumbnail; a raw without one answers "This RAW file has no preview Dalica can show".
  - Feature `heif` (off by default; `dalica` forwards it): HEIF/HEIC through `heic-rs` (pinned `=0.1.1`) in `formats::heif`, upright, 8-bit or 16-bit samples with alpha and ICC. Without it HEIC answers "HEIC support isn't included in this build". AVIF (also behind a `mif1` major brand) answers "AVIF files can't be displayed".
- **Public API (M8.6):**
  - `encode`: the encoders every file Dalica writes goes through (`data-model.md` §6). `Image` (borrowed 8- or 16-bit samples; `Channels` grey, grey + alpha, RGB, RGBA; `Image::rgba8`, `Image::from_decoded`), `Metadata` (the EXIF block TIFF-structured, the XMP packet, the ICC profile), `EncodeError` (every bad size, sample count, quality or block is an `Err`).
  - `encode::jpeg(image, quality, subsampling, metadata)` writes a baseline JPEG on the caller's thread (grey, or YCbCr at `Subsampling::S444` / `S420`; alpha ignored, 16-bit samples scaled to 8 bits; JFIF, then EXIF, XMP and ICC in APP1/APP1/APP2 segments, refused past one segment or 255 ICC chunks: `JPEG_EXIF_MAX`, `JPEG_XMP_MAX`, `JPEG_ICC_MAX`); `encode::jpeg_with_threads(…, threads)` encodes its restart-interval bands on scoped threads, the same bytes for any thread count. Our own encoder, ported from LightCraft (no new dependency).
  - `encode::png(image, metadata)` keeps the bit depth, channels and alpha, with `eXIf`, uncompressed `iTXt` (`XML:com.adobe.xmp`) and `iCCP` chunks (the `png` crate, `Compression::Fast`).
  - `jpeg_quality::{read, quality, subsampling}`: the quality (1–100) a JPEG was saved at, from the quantisation tables its frame selects, and its chroma `Sampling` (grey, 4:4:4, 4:2:2, 4:2:0, 4:4:0, 4:1:1, other; `Sampling::for_jpeg` writes 4:2:0 as 4:2:0 and anything else as 4:4:4). `None` for a header cut before its first scan, a table holding a zero, a frame selecting an undefined table; never a panic. Ported from PhotoCraft.
- **Public API (M8.8):** `jpeg_transform`, lossless rotation and flips in the DCT domain (our own, from ITU-T T.81): `transform(bytes, orientation, &limits)` turns a baseline or extended sequential Huffman JPEG (8-bit, any sampling) as `orient::apply` turns its pixels, with no requantisation (quantisation tables transposed for the transposing transforms), new optimal Huffman tables, the restart interval kept and every other segment (the EXIF orientation tag and thumbnail included) copied byte for byte. It answers `Refusal::NotLossless(_)` (a partial MCU moved to a leading edge; progressive, arithmetic, 12-bit, lossless or hierarchical files; data after EOI; layouts it does not handle) for the orientation-tag fallback, and `Refusal::Damaged(Error)` for damaged or over-limit files. `read` gives the quantised `Coefficients`, `Coefficients::{transformed, allows}` the same transform in memory, `encode` coefficients back to a baseline file. `tests/jpeg_transform.rs` checks all eight transforms at 4:4:4, 4:2:2, 4:2:0 and grey.
- **Public API (M10.56):** release builds leave the `heif` feature out (no HEVC licence). Without it `formats::heif::header` reads the container with `formats::heif_items::header` (pure Rust, no HEVC, on the `bmff` walk): the primary item's `ispe` size, its `irot`/`imir` as the orientation and EXIF from the `Exif` item's `iloc` extents (`MAX_ENTRIES` = 65,536 per `iloc`/`ipma`, `MAX_EXIF` = 4 MiB), so a HEIC is listed with its size and date while `decode` and `embedded_thumbnail` answer the tile text; an unusable container is the tile too, and bytes that stop inside a top-level box are `Truncated` (read on). `formats::hint(Format)` / `formats::hint_for(reason)` give the hint drawn under a tile's text (`heif::HINT`, only without the feature).
- **Public API (M15.2):** `Format::Video(VideoKind)` (`Mp4`, `M4v`, `QuickTime`, `Matroska`; `VideoKind::ALL`, `name()`; `Format::ALL` stays the still-image formats), sniffed by content in `formats::video::recognise` (ISO BMFF brands naming MP4, M4V or QuickTime and no still-image or sound-only brand; QuickTime movies without `ftyp` by their first box; Matroska by its EBML DocType, from the first 32 bytes). `formats::video::probe(bytes, &Limits)` / `probe_as(kind, …)` / `probe_file(path, &Limits)` → `VideoInfo { kind, duration_ms, size, rotation, created, video_codec, sound_codec, frame_rate, has_sound, location }` (`display_size()` after the rotation), through `bmff`'s walk (`video/mp4.rs`) and our own bounded EBML reader (`video/ebml.rs`, `video/mkv.rs`; RFC 8794 and RFC 9559); `video::iso6709` parses ISO 6709 text. Every image path (`read_header`, `decode`, thumbnails) answers `Unsupported` with "This video can't be played" until frames are decoded (M15.15). `tests/video.rs` builds MP4, M4V, MOV and MKV files from the documented layouts; fuzz target `video_probe`.
- **Test it alone:** `cargo test -p dalica-image` (no window, GPU, network or personal photos needed); `cargo test -p dalica-image --features heif --test heif` for HEIF. Every other file in `tests/` is a module of one test binary, `tests/all.rs` (`cargo test -p dalica-image --test all tiff::` runs one); `DALICA_FULL_TESTS=1` (the review gate) runs every test at full strength, the default is quick (at most 32 proptest cases). Test photos come from `dalica-scenes`; truncation at every byte offset and corruption of real files (proptest) never panic, and `tests/decode.rs` sends random bytes behind every format's magic number through every entry point. `tests/encode.rs` holds the encoders to a PSNR floor per quality, the same bytes on any thread count and metadata read back, with `fingerprints/encode-*.json`; `tests/jpeg_quality.rs` estimates scenes and our own JPEGs within 2. `tests/decode.rs` compares decodes by fingerprint (8 × 8 grid of per-channel mean and deviation) and writes actual/expected PNGs to `target/test-output/image/` on a mismatch. `tests/color.rs` builds its own tagged files (v4 profiles from `moxcms`, v2 ones from a small writer, CMYK/YCCK JPEGs from a DC-only encoder) and keeps `fingerprints/color-*.json` (`DALICA_BLESS=1` rewrites them). Dev builds compile this crate and `zune-jpeg` at `opt-level = 3`.
- **Corpus tests (M5.15):** feature `corpus` (off by default) compiles `tests/corpus.rs`, which reads the pinned real-file corpora in `corpus/` (PngSuite and 26 camera raws today; the `photos` and `heif` sets once they are published) and holds each set to its floors in `tests/corpus_floors.json` (files sniffed as their extension says, headers read the way scanning reads them, full decodes, 256 px thumbnails, embedded thumbnails decoded, PngSuite's corrupt files refused). A missing or stale corpus fails. Run `cargo xtask corpus --all`, then `cargo xtask test-corpus` (`--release --features corpus,heif`; `docs/development.md` §11). Floors only rise.
- **Fuzz it:** `crates/image/fuzz` is a separate cargo-fuzz workspace (nightly, excluded from the root workspace) with one target per parser of `security.md` §7.1: `sniff`, `decode_any`, `decode_<format>` for every format module, `raw_preview`, `embedded_thumbnail`, `icc`. `cd crates/image/fuzz && cargo +nightly fuzz run decode_jpeg`; the Fuzz workflow builds them and runs each for 60 s at every milestone review, and when dispatched by hand.
