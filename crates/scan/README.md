# dalica-scan

**Layer L3.** Watched-folder rules, walks, change detection, `notify` events, offline volumes and card/folder import; turns what it finds into `Op`s.

- **May depend on:** L0–L2 (`docs/architecture.md` §2; `cargo xtask layers` enforces it).
- **Public API:**
  - `scan_streaming(roots, &Options, emit) -> Summary` (M5.4): walks the roots a folder at a time through `dalica-fs` (depth 32, 1 000 000 entries, folder links followed after the real tree with loop detection, FIFOs and devices never opened) and hands each `Event` to `emit` as it happens: `Folder` (a folder's photos, complete, as soon as it is read: depth first, each folder before its subfolders, in name order), `Progress` (`folders_done`, `folders_queued`, `files`, `found`, `failed`, after every folder and every 256 files inside a big one), `Failed` (a file's first failure) and `Warning`. `emit` returning `false` (`|e| tx.send(e).is_ok()` on a channel whose receiver is gone) stops the scan like `Options::cancel`. A stopped scan stops before the next file: the folder it was reading is not handed out and the root it was walking is not in `Summary::walked`, so the verification pass never removes what it did not see.
  - `Options` (owned, `Clone + Send`): `types` (`FileTypes`, Options → File Types), `skip` (`SkipRules`), `excluded` (subtrees set to Remove under a watched root: never listed, never entered; an excluded root counts as walked and empty), `cancel` (`Arc<AtomicBool>`, checked before every folder and every file, and by the reading thread before each file it takes), `failures` (the last scan's `Summary::failures`), `budget` (10 s), `limits` (`dalica-image` limits), `reader` (the header reader; tests plant panicking or stalling ones).
  - `scan(roots, cancel)` and `scan_with(roots, &Options)` gather the same into one `Scan { walked, folders, warnings, failures, cancelled }`, folders sorted by path. A scan never fails as a whole.
  - `diff(&mut Library, &Scan)` → the ops (batches of at most `BATCH` = 500 photos) that make the model match the disk: new folders, removed / renamed / changed / added photos, folders gone. A delete plus an add with the same size and mtime in one folder is a rename (id and star kept). Folders under roots that could not be walked are never removed. A streaming caller diffs each `Folder` as it lands with an empty `walked` (no folder is removed), and once more at the end with every folder path and `Summary::walked`; `diff_found(&mut Library, &FoundFolder, gone)` diffs one folder at a path the model does not know once the walk ended, pairing it with the gone folder it is a rename or move of (ids kept) and removing nothing.
  - `meta` (M6.32, `xmp-interop.md` §5, §7): `Options::metadata` = `ReadMetadata::Off` (default) or `NewOrChanged(Arc<Known>)` (`Known::of(&Library)`: the files the model knows at their size and time; `ReadMetadata::all()` reads every photo). The owned fields of each new or changed photo are read into `FoundPhoto::file` (`FileValues`, cleaned as the library stores them): a JPEG, PNG, WebP or TIFF on the reading thread, with its header and from the bytes the header read (`Options::bytes_reader`, a `HeaderBytesReader`: `default_bytes_reader()`; set it to `None` when planting `reader`), read again only when those are not enough (a JPEG up to its image data, the others whole, at most `MAX_FILE`, 1 GiB); a RAW on the scan's thread through its `.xmp` sidecar whatever the write option, else a TIFF-structured RAW's embedded XMP; each read inside `catch_unwind`, an unreadable file brings `None`. `diff` then follows `dalica_library::sync`: a new photo Dalica has nothing for takes every value its file has in its `AddPhotos` batch (a rating of 5 as a star), and the last op is the sync op `Batch[Batch(imports), Batch(first-scan fills), SetSynced, SetFacts]` (`meta::sync_parts`, `undo_of_import`, `conflicts`, `ours_of` for the engine). The place is read and synced, never imported (no per-photo place yet).
  - `originals` (M8.9, `data-model.md` §6): `read(folder, now) -> Originals::{Absent, Read { saved, notes }, Unreadable, SetAside { why, kept }}` reads a folder's originals record on the scan's thread (never through a link; a damaged one kept as `.dalica.json.corrupt-<time>`), `pending()`, `ops(&Library, folder, &found)` and `changes(&Library, &[(name, id)], &found)` give the derived `SetSaved` (an absent record clears, an unreadable one changes nothing), `saved_as(&Sidecar, name)` and `project(&Sidecar)` read what a new photo or folder takes. The walk fills `FoundPhoto::saved_as`, `FoundFolder::project` and `FoundFolder::originals` (what the record could not give becomes a `Warning`), and `diff` puts `SetSavedAs` in the `AddPhotos` batch, `SetProjects` in the `AddFolder` batch and one `SetSaved` after the adds, so a scan alone brings M8's data back.
  - `facts` (M9.7, `organizing.md` §8): the search facts read with a photo's metadata in the same pass, `facts::of(format, &Metadata)` (camera make and model from IFD0, video by type, geotagged when the file holds a usable GPS location) and `facts::of_header(&Header)` for the RAW containers `dalica-meta` does not read; made safe and capped (`camera`, `MAX_CAMERA`). They ride in the sync op's `SetFacts` (derived: no undo step, no revision).
  - M9's sidecar fields (M9.10, `data-model.md` §3, §3.2): the walk fills `FoundPhoto::albums` (`photo_albums(&Sidecar, name)`: memberships with their position keys), `FoundFolder::sort` (`folder_sort`: `sort` `name` / `size`, else by date, and `reverse`) and `FoundFolder::album_names` (`album_names`: the top-level names, cleaned), with `dalica-store` `mapping`'s rules (a test in `dalica-engine` `scanning.rs` holds the two readings together); `FoundFolder::sidecar_unread` says a sidecar was there but could not be read. `diff` leaves them alone: the engine puts them into the ops that add a folder or photos (it alone knows the albums and `albums.json`).
  - M13's sidecar fields (M13.45, `data-model.md` §3, §7): the walk fills `FoundPhoto::faces` (`photo_faces`: the faces Dalica can hold, in file order; entries it cannot use, those past 256 and empty rectangles left out, faces naming any person kept), `FoundPhoto::geo` (`photo_geo`: `[lat, lon]` → `Geo::At`, `null` → `Geo::Removed`, no key or a wrong one → none) and `FoundFolder::people` (`folder_people`: the top-level names and nicknames, cleaned), by `dalica-store` `mapping`'s rules (`read_photo`, `read_people`; the same test in `dalica-engine` `scanning.rs` holds them together). `diff` leaves them alone too: the engine adds the people the faces name, then `SetFaces` and `SetGeo`, to the ops that add the photos.
  - `volumes`: `Places` (Pictures, Documents, Desktop, Home: `Places::system()` from `HOME`/`USERPROFILE` and, on Linux, the XDG user-dirs file; everything under `$DALICA_PLACES_HOME` when that is an absolute folder; `Places::under(home)` and `Places::from_env(var)` for tests; `existing()`, `first_run()`), `volumes()` (the startup disk first: Linux `/proc/self/mounts`, macOS `/Volumes`, Windows drive letters C–Z; `parse_mounts` and `volumes_in(parents)` for tests), `online(root)` (a folder that can be reached), `children(path)` (subfolders for the Folder Manager, skip rules applied, sorted by name, at most `CHILDREN_CAP` = 1000 with `truncated`). These read the disk (a sleeping network volume can stall them): call them off the UI thread.

  - `devices` (M11.5, `organizing.md` §3 item 1; ported from LightCraft, see `NOTICE`): `Device { kind, name, root, folder }`: a `Card` is a mounted volume holding a `DCIM` folder (`dcim_in`: `DCIM`, `dcim`, or another spelling off Windows; a link is not followed) and imports from it; a `Drive` is another `VolumeKind::Mounted` volume of `volumes()` and imports from its root; the startup disk and network shares are neither. `name` is the volume's own name, "Removable drive (E:)" for a drive letter (`display_name`). `devices()` never touches the disk: a `DeviceWatch` serves the last listing and starts one background listing (coalesced, no lock held while it runs) when it is older than `MAX_AGE` (2 s); `devices_now()` lists on the calling thread; `on_change(f)` runs when a listing changes the list. `$DALICA_DEVICE_ROOTS` (paths joined like `PATH`; `device_roots`) replaces the platform's volumes with the folders inside those mount folders; `devices_in(parents, volumes)` for tests (links among the mount folders are skipped: macOS lists the startup disk as one).
  - `import` (M11.5, `organizing.md` §3 items 1–2, `security.md` §5.9): `list_source(root, &ListOptions, emit) -> Listing` lists a card, a drive or a folder as an untrusted tree: walked through `dalica-fs` (depth 32, loops detected, skip rules applied, FIFOs and devices warned and never opened, at most `MAX_FILES` = 100 000 files, `truncated` past it); each regular file recognised by its content under `ListOptions::types` (only its first bytes read when it is no picture or its type is off) and otherwise read once, in 64 KiB chunks, never by the reported size (at most `MAX_KEPT` = 256 MiB kept, `MAX_READ` = 16 GiB read): a `Candidate { index, path, relative, name, exact_name, size, modified, captured, time_source, format, width, height, digest, thumbnail, problem }` with its `md5:` digest of every byte read, its capture time (`dalica-meta`'s owned date for JPEG, PNG, WebP and TIFF, else the header's EXIF, else the file's time as UTC: `TimeSource`), and a thumbnail of at most `THUMBNAIL` = 256 px (the embedded one, upright, when it decodes, else a scaled decode). A name that is not valid Unicode is shown lossily (control and bidirectional characters replaced by U+FFFD, `exact_name` false) and the file is opened only by its own name. Events: `Walked` (the file count), `Batch` (at most `BATCH` = 16 candidates, or what 200 ms gathered), `Progress { files, done, listed }`, `Warning`. The cancel flag (and `emit` returning `false`) stops it between files. `Listing::groups`: `groups(times)` sorts by capture time and splits where neighbours are more than `GROUP_GAP` (2 hours) apart. `list_all` gathers it all.

  - `rules` (M5.12): `Rules` (Scan Always, Scan Once, Remove and the faces flag per folder; a folder's mode is its nearest explicit ancestor's), `Rules::verification` (the units to verify), the excluded subtrees passed to `Options`.
  - `watch` (M5.11): the `Watcher` (the `notify` 8 backend, the pure-Rust polling fallback per root for network shares and failed watches), dirty folders debounced, coalesced and capped (deepest folders fold into their parents, nothing dropped); `watch::rescan` and `diff_rescan` verify only the dirty folders and equal the full diff restricted to them; folder renames and moves are detected by their photos (size, mtime) and keep their ids; nothing is removed under a root that cannot be walked; a full-verification `Schedule`. Tests: `tests/watch.rs`, `tests/incremental.rs`, `tests/rules.rs`.

## What a scan lists

Every file is recognised by its content (`dalica_image::sniff`), never by its name: a `.jpg` that holds a PNG is a PNG, text named `.jpg` is nothing. Every recognised format is listed unless its `FileType` is turned off (JPEG is always on); a format `dalica-image` does not decode yet, and a file whose header cannot be read, is listed at 0 × 0 (the thumbnail job gives the reason). Formats `dalica-image` learns to read are sized without a change here; a format it adds beyond today's list falls under the RAW toggle.

Each file is read inside a per-file guard (`security.md` §4.3): on a reading thread, inside `catch_unwind`, within `Options::budget` (10 s). The thread reads up to 16 files ahead of the one waited for. A file that fails (a header error), panics or overruns the budget becomes a `Failure { path, size, mtime, format, reason }`: reported once as `Event::Failed`, kept in `Summary::failures`, and, given back in `Options::failures`, not read again (still listed at 0 × 0 when its format was recognised) until its size or modification time changes. A thread that overruns is abandoned and a fresh one takes the next file.

## Skip rules

One module (`src/skip.rs`); names compared ignoring ASCII case. A skipped folder is never entered.

| Rule | Where | Names |
|---|---|---|
| Dot entries | files and folders, everywhere, every system | any name starting with `.` (`.dalica.json`, `.git`, `.Trashes`, `.Spotlight-V100`, `._IMG_0001.JPG`, …) |
| Dalica's originals | everywhere | `.dalica-originals` |
| OS, NAS and tool folders | everywhere, every system | `$RECYCLE.BIN`, `System Volume Information`, `lost+found`, `@eaDir`, `#recycle`, `#snapshot`, `@Recycle`, `@Recently-Snapshot`, `@SynoResource`, `node_modules`, `__pycache__`, `$WinREAgent`, `Config.Msi` |
| Bundles, other programs' libraries and preview caches | everywhere, every system | names ending `.app`, `.photoslibrary`, `.photolibrary`, `.aplibrary`, `.lrdata`, `.cocatalogdb` |
| Windows caches | everywhere on Windows | `AppData`, `Temporary Internet Files`, `INetCache`, `$Windows.~BT` |
| Windows system folders | at the top of a drive | `Windows`, `Program Files`, `Program Files (x86)`, `ProgramData`, `Recovery`, `PerfLogs`, `MSOCache`, `$Windows.~WS`, `$SysReset` |
| macOS system folders | at the top of the startup disk | `System`, `Library`, `Applications`, `private`, `usr`, `bin`, `sbin`, `dev`, `cores`, `opt`, `etc`, `tmp`, `var`, `Volumes` |
| macOS home caches | at the top of a home (`/Users/<name>`) | `Library` |
| Linux / Unix system, cache and temp folders | at the top of `/` | `proc`, `sys`, `dev`, `run`, `tmp`, `var`, `boot`, `efi`, `snap`, `usr`, `etc`, `bin`, `sbin`, `lib`, `lib32`, `lib64`, `libx32`, `opt`, `srv` |
| Linux / Unix home caches | at the top of a home (`/home/<name>`) | `snap` |

The same names deeper down (a `Library` or `tmp` folder inside Pictures) are the user's own and are scanned. Images smaller than 64 × 64 are listed; hiding them is the view's job (View → Small Pictures).

## File Types

`FileType`: `jpeg` (always on), `png`, `gif`, `bmp`, `tiff`, `webp`, `heif`, `avif`, `jxl`, `psd`, `raw`, `video` (stable ids for settings and the control API). `FileTypes::all()`, `jpeg_only()`, `with(type, on)`, `allows(type)`.

## Test it alone

`cargo test -p dalica-scan` (no window, GPU, network or personal photos needed). The integration tests are one binary (`tests/all.rs`, one module per file: `cargo test -p dalica-scan --test all <file>::` runs one); a task's gate runs them quick, `DALICA_FULL_TESTS=1` at full strength (every size):

- `tests/scan.rs`: temp trees of `scenes` photos; the verification pass emits exactly the ops for an add, a delete, a rename and a rewrite; an excluded subtree is never walked; a folder's photos arrive while a later folder is still being read, and progress rises to the totals (inside a big folder too); a cancelled scan stops at the next file; a planted panicking or stalling file is reported once and not read again until its modification time changes; a FIFO never blocks a scan; 1000 JPEGs are scanned and timed (40 in a task's gate).
- `tests/meta.rs`: what is read (JPEG, PNG, a RAW's sidecar, an unreadable JPEG) and only for new and changed files; a first scan's import in the `AddPhotos` batch; a rescan's import and its undo; both changed named by `meta::conflicts`; a sync op decided again after a model change; truncated and damaged files never panic.
- `tests/originals.rs` (M8.9): a record becomes derived saved records while the walk skips `.dalica-originals`; hostile names and values past the caps kept and not used; a damaged record set aside; a file or link in place of the folder not followed; a scan alone brings back saved records, copies saved beside and the project mark, and a second scan changes nothing.
- `tests/facts.rs` (M9.7): camera make and model from a JPEG's, a PNG's, a TIFF's and a RAW's EXIF; the GPS location from EXIF and from XMP (a RAW's `.xmp` sidecar); hostile blocks give no facts and never a panic; the diff carries the facts as derived data, only for new and changed files.
- `tests/albums.rs` (M9.10): the walk reads each photo's memberships, the folder's sort and its album names with entries Dalica cannot use left out; a folder without a sidecar says nothing and one whose sidecar cannot be read says so; `diff` makes no album op (the engine does, `crates/engine/tests/albums.rs`).
- `tests/skip.rs`: each skip rule on a temp tree, for each system's rules; each toggle drops exactly its format; content wins over names.
- `tests/devices.rs` (M11.5): with temp folders as mount folders, a volume holding `DCIM` or `dcim` is a card and one without a drive, a link to the startup disk is skipped; only mounted volumes count and a drive letter gets its display name; a slow listing never blocks `get`, requests are coalesced and a new card arrives with a change notice.
- `tests/import_source.rs` (M11.5): a source of `scenes` photos lists every picture with its EXIF or file time, digest and thumbnail (embedded or scaled), grouped at 2-hour gaps; File Types apply; a FIFO, a link loop, a tree past the depth limit and a JPEG whose header claims 60 000 × 60 000 are bounded and reported; the file cap truncates; cancel (and a receiver gone) stops between files; a non-UTF-8 name is listed and never opened by its lossy form (Linux).
- `tests/volumes.rs`: places honour the override and the XDG file; the first run never offers the home; `children` of a 10 000-folder tree stays within its cap (40 folders and a cap of 16 in a task's gate); a renamed-away root is offline; mount tables and mount folders list their volumes.
