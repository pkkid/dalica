# dalica-fs

**Layer L0.** Every write to the user's disk: atomic replace + fsync + verify, the read-before-write guard, the library lock, move/copy with verify, the OS trash, bounded walks, the UI-thread guard and fault-injection points (feature `faults`).

- **May depend on:** `core` (`docs/architecture.md` §2; `cargo xtask layers` enforces it). External: `thiserror`; on Unix `rustix` (safe API only, feature `fs`) for writes relative to a held folder handle. The lock uses std's `File::try_lock`.
- **Public API:**
  - `atomic`: `read(path, limit)` → bytes + `Identity`; `replace(path, bytes, Expect::Absent | Expect::Unchanged(id))` → new `Identity` (the target's folder validated and held once, then temp file next to the target, fsync, identity re-check, rename, folder fsync, read-back, all relative to that folder: on Unix a directory handle through `rustix`, on Windows the folder's identity re-checked before each step; `security.md` §5.6); `identity`, `is_temp_name`. Final symbolic links are refused, and so is a folder swapped for a link before it is opened; a swap after it leaves the write in the original folder. `replace_private` is the same for a credential: the temporary file is created owner-only (0600 on Unix).
  - `originals` (`data-model.md` §6, `security.md` §5.3): `back_up(folder, name, photo_identity, kept)` moves a photo into `<folder>/.dalica-originals/<name>` by one rename that never replaces, after re-checking its identity, or answers `AlreadyKept` when the recorded backup (`Recorded`: size and the caller's digest check over its bytes) is already there; `restore(folder, name, Expect, kept)` moves the recorded backup back over the saved file (`Expect::Unchanged`) or into its free name (`Expect::Absent`); `ensure_dir(folder)` opens or makes the backup folder. All relative to the held folder: a link in place of the backup folder, the backup or the photo is refused, and so is a backup that is not the recorded one, with nothing moved.
  - `create` (`security.md` §5.4): `new_file(folder, name, bytes)` → `Created { name, identity }`: a temporary file, `fsync`, then the first free name of `core::names::candidates` taken by a rename that never replaces (`renameat2(RENAME_NOREPLACE)` on Linux/Android, `renameatx_np(RENAME_EXCL)` on Apple, a hard link then unlink elsewhere; exclusive creation on volumes without links), folder `fsync`, read-back; `new_folder(parent, name)` makes `<name>` or the first free `<name>-NNN`; `plain_name` is the one-plain-component check both use (hostile names are refused with nothing written).
  - `append`: `Appender` / `append(path, bytes, cap)` (append-only, fsync per record, never past the cap) and `rotate(path, keep)` (`name.log` → `name.1.log` → `name.2.log`).
  - `dirs`: `create_dir_all`; `create_private_dir_all` (new folders 0700 on Unix); `remove_own_file` (a file Dalica made for itself, such as a token file; missing is fine, a folder is refused); `TempDir::new(prefix)` makes a new private `<temp>/<prefix>-<pid>-<n>` (never an existing one) that `close()` or drop removes with its contents. `aside`: `set_aside(path, tag)` renames a damaged file to the first free `<name>.<tag>[-NNN]`.
  - `guard`: `mark_ui_thread()` returns a guard; while it lives, every call on that thread returns `Err(OnUiThread)` in debug and test builds.
  - `faults` (feature `faults`): named points (`faults::points`; `ATOMIC_POINTS` starts with `atomic.open_dir`, `STALE_POINTS`), `arm` (this thread), `arm_global` (any thread), `run_at(point, hook)` (runs a closure just before the step, to plant a change such as a folder swapped for a link), `arm_full` / `arm_full_global` (the step fails and cleans up as for `Fault::Error`, with the OS's own full-disk error, `disk_full()`: `ENOSPC` or `ERROR_DISK_FULL`, `ErrorKind::StorageFull`), `disarm_all`; `BACKUP_POINTS`, `RESTORE_POINTS`, `NEW_FILE_POINTS` (with `create.no_links`, which armed as an error simulates a volume without links, then `NEW_FILE_DIRECT_POINTS`) and `NEW_FOLDER_POINTS` for M8.2's modules; `Fault::Error` fails a step, `Fault::Crash` stops without cleanup.
  - `pack`: what a packed cache needs from the disk: `PackFile` (append-only, positioned reads, `sync`, `truncate` of a torn tail), `TempFile` (a streamed `.<name>.dalica-tmp-<16 hex>` committed by one rename), and `list_shaped` (→ `CacheFile`s) / `remove_shaped` (only regular files of the cache's own name shape).
  - `stale`: `remove_stale_temps(folder, now)` → `StaleTemps { removed, errors }`: removes only regular files of exactly the `is_temp_name` shape last modified more than `STALE_AFTER` (24 hours) before `now`, in that folder only (at most `LIST_LIMIT` entries looked at), never a link, a folder or another name (`security.md` §5.8).
  - `lock`: `LibraryLock::acquire(dir)` takes `<dir>/lock` (an OS file lock, released however the process exits) or returns `Err(Locked)` at once.
  - `walk`: `walk(root, Limits, skip)` → `Walk { entries, warnings }`: depth 32, 1 000 000 entries, folder links followed after the real tree with (device, inode) loop detection, children sorted by name, results in pre-order; unreadable parts, limits, loops and cancellation become warnings.
  - `Error`.
- **Test it alone:** `cargo test -p dalica-fs` (no window, GPU, network or personal photos needed). Tests always build with `faults` (self dev-dependency), so the fault loops run in every `cargo test` of this crate. This is the one crate whose fault points are enumerated exhaustively; crates that use it test one point per class (`docs/development.md` §6). In a test build (`faults` in a debug build) the real `fsync` is skipped and `trash` uses a stand-in folder of the process instead of the OS trash (`faults` module docs); `tests/sync.rs` turns real syncing back on and `trash::the_os_trash_round_trips` the OS trash. `tests/crash.rs` kills a child process (this test binary as a helper; `SIGKILL`, `TerminateProcess`) at a random moment while it replaces a file or runs the originals backup of a Save and its Undo, then checks the old or the new bytes are whole and the original is under exactly one name (5 kills each quick, 50 at full strength). `tests/refusals.rs`: a full disk at every step of a replace, a new file and a copy (the reason the user reads, nothing left behind), a real `RLIMIT_FSIZE` limit in a child (Unix), a read-only folder refusing each step of a Save and a move or copy into it before anything is written (Unix; skipped when the process may write there anyway), two names with one identity (a hard link standing in for a share that reports inode 0) never letting a case rename replace, and a folder removed before the rename of a replace, a move, a copy and a cross-volume move. The integration tests are one binary (`tests/all.rs`, one module per file: `cargo test -p dalica-fs --test all <file>::` runs one); a task's gate runs them quick, `DALICA_FULL_TESTS=1` at full strength (every property case, every size).
