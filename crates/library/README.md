# dalica-library

**Layer L2.** The in-memory model (folders, photos, albums, people, tags, captions, stars, hidden, recipes, places), `Op`s with inverses, revisions, queries and the search grammar.

- **May depend on:** `core` only; it stays pure (`docs/architecture.md` §2; `cargo xtask layers` enforces it). External: `serde`, `thiserror`.
- **Public API (M1.8):**
  - `Library`: `apply(Op) -> Result<Op>` applies an op completely or not at all, bumps `revision()` once and returns the inverse. `folder_revision(id)` says when a folder last changed. `next_folder_id` / `next_photo_id` never reuse an id.
  - `Op` (serde-tagged, one journal record): `AddFolder`, `RemoveFolder` (with its photos), `AddPhotos`, `RemovePhotos`, `UpdatePhotos`, `SetStars`, `Batch`.
  - `Folder { id, path }`, `Photo { id, folder, name, size, mtime, width, height, date, star }`, `Model` (the comparable content).
  - Queries: `folder`, `photo`, `folders`, `photos`, `folder_by_path`, `photo_by_name`, `photos_in` (capture date oldest first, then name), `folders_in_display_order` (newest folder date first), `folder_date`, `starred`.
- **Sketches (M4.2):** `Sketch` (1 to `MAX_SKETCH` bytes, base64 in JSON), `Op::SetSketches`, `Library::sketch`, `sketches`, `sketch_count` and `thumbnail_revision`. Sketches are derived data (`Op::is_derived`): journaled, never undone by the user, they move the thumbnail revision instead of the library revision.
- **The tree (M4.4, `tree.rs`):** `Tree::build(library, roots, options)` gives the library tree's groups (Albums, People, Projects, Folders, Other, Hidden Folders), rows, counts and light-table sections for `TreeOptions` (flat or tree mode, the four folder sorts and reverse, collapsed groups and nodes, Small and Hidden Pictures, offline roots). Hidden folders and photos come from the model: with Hidden Pictures off they leave the tree and the sections; with it on a hidden folder sits in Hidden Folders (flat mode) or in its place marked hidden (tree mode). Dates are effective dates, and a folder date set in Folder Properties beats its oldest photo's.
- **M6 fields (M6.2):** what the user says about a photo is a `PhotoInfo` (caption, tags, hidden, recipe `edits` and `redo` as opaque operation strings, a `date` of the user's) held beside `Photo` (which is what the file says), so a rescan never touches it; a folder's is a `FolderInfo` (description, date, place, hidden). Empty infos are not stored. `Library::info`, `infos`, `caption`, `tags_of`, `is_hidden`, `effective_date` (the user's date, else the file's), `sort_date` (that, else the file time), `folder_info`, `folder_infos`, `is_folder_hidden`. The last-synced hashes of the owned metadata fields (`xmp-interop.md` §5) are a `Synced` per photo (`synced`, `synced_all`): derived data like sketches, moving no revision.
  - Ops, each batched over any number of photos or folders and returning its exact inverse: `SetCaptions`, `AddTags`, `RemoveTags`, `RenameTag` (everywhere; onto an existing tag it merges), `SetTags`, `SetHidden`, `SetRecipes`, `SetDates`, `SetPhotoInfo` (everything at once: rebuilds, and the inverse of removing photos), `SetFolderInfo`, `SetFoldersHidden`, `SetSynced` (derived). Removing photos or a folder takes their info, synced hashes and sketches; the inverse puts them back.
- **M8 fields (M8.1, `data-model.md` §6):** a photo's `Saved` record (the whole recipe the saved file holds, the kept original's size, modification time, pixel size and digest, `SaveState::Pending` or `Done`, the time of the save) is index-only like the sketch: it comes from `.dalica-originals/.dalica.json`, `Op::SetSaved` is derived (no undo step, no revision bump), so loading records moves no cache. A photo's `SavedAs` (the JPEG written beside a photo Dalica cannot write in place, and the recipe it holds) and a folder's `Project` mark (`Exported`) are sidecar fields with ordinary undoable ops, `SetSavedAs` and `SetProjects`. `saved`, `saved_all`, `saved_as`, `saved_as_all`, `project`, `projects`. Removing photos or a folder takes them; the inverse puts them back. Caps: a digest at most `MAX_DIGEST` (256) bytes, a copy's name not empty and at most `MAX_FILE_NAME` (1 KiB), recipes as above.
  - The ops of M8's file changes, each one batch with an exact inverse, built from the model: `save_op` (records set, recipe and redo list cleared), `undo_save_op` (record cleared, the recorded recipe put back in front of newer edits, the redo list kept), `revert_op` (record, recipe and redo list cleared); both refuse a photo without a done record (`Error::NotSaved`). `save_beside_op` records the copy with the current recipe, which the photo keeps.
  - Queries: `has_unsaved_edits` (a recipe that is not empty and not the one `savedAs` holds; the redo list does not count), `unsaved_count` / `unsaved_counts` per folder (hidden photos included; worked out once per revision, kept by derived ops), `unsaved_in` (display order), `can_undo_save` and `can_revert` (a done in-place record), `unrenderable(id, renders)` (the first operation of the recorded recipe, then the recipe, that `edit`'s parse says cannot be rendered: the library stays core-only, so the caller passes the parse).
  - The tree puts folders with a project mark in Projects in flat mode wherever they are (with the folders under `projects_dir`); tree mode keeps them under their parents; a hidden one goes to Hidden Folders.
- **M9 fields (M9.1, `data-model.md` §2–§4 and §8, `organizing.md` §4):** held in maps of their own beside `Photo` and `FolderInfo`.
  - **Albums:** `AlbumInfo` (name, description, date with `use_newest`, place; caps `MAX_ALBUM_NAME` 1 KiB, `clean_album_name`), memberships with `core::PosKey` position keys, covers (a cover is always a member: when it leaves, it is cleared in the same op and the album shows its first photo). Ops, each batched with an exact inverse: `CreateAlbums`, `DeleteAlbums` (every membership and the cover in the inverse), `SetAlbumInfo`, `AddMembers`, `RemoveMembers`, `SetMemberKeys`, `SetCovers`. Album ids: `new_album_id(draw)` (`a` + 12 hex digits from the caller's random source, drawn again on a clash), `album_id_from`.
  - **Keys (`albums.rs`):** `album_add_op` (after the last key, or at an `Anchor::Before`/`After` a member; members already in it stay), `album_reorder_op`, `album_sort_op` (Sort Album By: every key rewritten), `album_rekey_op`. Only the moved photos get new keys; when no key fits (equal neighbours, or a key would pass 512 bytes) the whole album is re-keyed in the same op. A drop finds its neighbours through a per-album key index, without sorting the album.
  - **Files:** `MovePhotos` (to another folder and/or a new name; id and everything said about the photo kept; names one plain path component), `MoveFolder` (with every library folder under it, ids kept; refused into itself, onto a folder it is in, or over a library folder at the target), `SetFolderSorts` (`PhotoSort`: `SortBy::Date | Name | Size` and `reverse`; the default is not stored). Removing photos or a folder takes memberships, covers, facts, digests, times and the folder's sort; the inverse puts them back.
  - **Index-only, derived (no undo step, no revision bump on load):** `Facts` (camera make and model, video, geotagged; `SetFacts`), `ContentDigest` (valid only while the file keeps its size and modification time: `content_digest`; `SetDigests`), first-indexed and last-changed times (`SetFirstIndexed`, `SetLastChanged`; `first_indexed_op(ids, now)` for a scan). `stamped(op, now)` adds the last-changed time of every photo whose data `op` changes as one batch, so the journal replays it and the inverse undoes it.
  - **Queries (cached until the next change they read):** `album_members` (by key; equal keys by folder path, then file name), `starred_photos` (by date), `recently_updated(now, days)` (by `updated_at`: the later of the last-changed time and the file time, the file time only when after the first-indexed time; a photo never changed since it was indexed is left out; newest first), `album_stats` / `album_date` (its own, else its newest photo's) / `album_count` / `album_cover`, `albums_of`, `member_key`, `sorted`, `photos_sorted` (a folder's own sort).
  - **The tree:** `AlbumTree::build` gives the Albums group (the search album while searching, Starred Photos and Recently Updated when they show a photo, then user albums in the folder sort), `Section` (`folder:12`, `album:starred`, `album:recent`, `album:search`, `album:a91c0e`; `FromStr`), `AlbumTree::sections_with` (album sections before folder sections), `section_photos` (each section's photos in its order), and `TreeOptions::filter` (`SectionFilter`, search mode: sections without a match drop out in flat and tree mode), `search`, `now`, `recent_days` (default `RECENT_DAYS`, 30). `Tree` keeps its folder rows and `SectionId`, so the UI's matches on them stand.
- **Search (M9.8, `search/`, `organizing.md` §8.1–§8.2):** `search::Parsed::new(text)` reads the search box (words AND, `-word` NOT, `tag:` and `camera:` fielded, `person:` and `color:` read but reported in `unavailable`, an unknown `name:value` as plain words; tokens split at whitespace and ASCII punctuation, prefix matches ignoring case, a date spelling kept whole; caps `MAX_QUERY` 1 KiB, `MAX_WORDS` 32, `MAX_TERM` 64 bytes, past them `truncated`). `Query` (text, `Filters` Starred/Faces/Videos/Geotagged, `Age` in days from a given now, read on the sort date) and `Scope` (Hidden and Small Pictures, the light table's sections in order, the clock for Recently Updated; `Scope::from_options`). `Extract::from_library` is an owned copy of what search reads (`PhotoDoc`, `FolderDoc`, `AlbumDoc`); `Update::for_op(library, op)` reads again what an applied op touched. `SearchIndex::build` / `from_library`, `apply(update)` (photo by photo, never a rebuild), `search(query, scope)` → `SearchResult` (ids in light-table order, `sections` with counts, the search album first, `folders`, `bytes`, `unavailable`, `truncated`), `suggest(text, scope, limit)` → `Suggestion`s (`SuggestionKind` tag, folder or album, with counts and sections; the last word; tags only after `tag:`; tags, then folders, then albums, each by count then name; entries with nothing shown left out; at most `MAX_SUGGESTIONS`, 100). `text_matches` and `Extract::matching` are the matcher's rule photo by photo, the reference the index is tested against. The engine keeps the index on a worker (M9.11).
- **Tags (`tags.rs`):** two tags are the same when equal after Unicode lowercase (`fold`); a photo never holds one twice; adding a tag in use takes the spelling in use, so the first spelling is kept; spellings imported from files stay, and the index shows the one most photos use (ties: byte order). `Library::tag_index()` (`TagIndex`: `count`, `spelling`, `counts`, `with_prefix` for autocomplete) is kept in step by every op; `Library::tag_counts_in(ids)` gives the partial counts of a selection (`PartialCount`, shown as "beach (3 of 8)").
- **Caps (`security.md` §4.4).** Ops refuse text past them (`Error::TooLong`, `TooMany`, `BadText`; the text is never in the message); `clean_caption`, `clean_description`, `clean_place`, `clean_tag` and `clean_tags` bring any text inside them (trim, control characters in tags and places made spaces, cut at a character boundary):

  | Text | Cap |
  |---|---|
  | caption (`MAX_CAPTION`) | 16 KiB (UTF-8 bytes) |
  | tag (`MAX_TAG`) | 256 bytes; trimmed, not empty, no control characters |
  | tags per photo (`MAX_TAGS`) | 1,000 |
  | folder description (`MAX_DESCRIPTION`) | 16 KiB |
  | folder place (`MAX_PLACE`) | 1 KiB |
  | operations per recipe or redo list (`MAX_OPERATIONS`) | 10,000 (the sidecar's own limit) |
  | one operation string (`MAX_OPERATION`) | 64 KiB |

- **Test it alone:** `cargo test -p dalica-library` (no window, GPU, network or personal photos needed). `tests/ops.rs`: for random op sequences with every op in the mix, applying an op and then its inverse restores the model and the tag index, each apply bumps the revision once (derived ops never), and the tag index always equals one counted from the photos. `tests/sketch.rs`: sketches. `tests/tree.rs`: the tree in both modes for every sort, hidden folders and photos, effective dates. `tests/tags.rs`: counts, partial counts, prefix lookup, the case rule, merging renames, the caps, and the build time of a 100 k-photo tag index (printed; 4 000 photos in a task's gate). `tests/m6_fields.rs`: each M6 field's op, undo and redo, journal names, synced hashes as derived data (removal and restore, and refused ops changing nothing, are `tests/ops.rs`'s properties). `tests/m8_fields.rs`: each M8 field's op and inverse, loading a record bumping no revision, the unsaved count through edits, Save, Undo Save, Revert and a Save beside, the cache per revision, refusals and caps, unrenderable operations, journal names. `tests/ops.rs` mixes M8's ops and batches in and checks the cached unsaved counts against fresh ones, and M9's ops (albums, the add, drop, reorder and sort ops, moves, folder moves, sorts, facts, digests, times, stamped ops), checking the cached album order, Starred Photos and Recently Updated against fresh ones and that drops land at the ends after any sequence. `tests/albums.rs`: album ops and refusals, 10 000 drops at one spot (keys under 10 bytes, times printed), repeated middle drops re-keying before 512 bytes, equal keys by path then name, Sort Album By, dates, covers, ids, journal names, and a proptest that drops land where they are dropped. `tests/m9_fields.rs`: facts, digests and times as derived data, stamping, Recently Updated on a virtual clock, moves and renames keeping every field, folder moves with subtrees, folder sorts, journal names. `tests/tree.rs`: the Albums group, the section filter in both modes, section photos and section names. `tests/search.rs` and `tests/search_props.rs`: the grammar per operator, dates, filters, age, hidden and small pictures, light-table order and sections, suggestions, updates per op, and a proptest that an index kept up to date equals one built from scratch and the reference matcher. The op generator both property files use is `tests/seed.rs`. The integration tests are one binary (`tests/all.rs`, one module per file: `cargo test -p dalica-library --test all <file>::` runs one); a task's gate runs them quick, `DALICA_FULL_TESTS=1` at full strength (every property case, every size).
