# dalica-sidecar

**Layer L1.** The `.dalica.json` folder sidecar: parse and print with unknown keys preserved; the read-only legacy reader and its conversion to Dalica's model.

- **May depend on:** L0 (`docs/architecture.md` §2; `cargo xtask layers` enforces it): `dalica-core` for dates. External: `serde_json` (with `float_roundtrip`), `thiserror`.
- **Public API (v1, M1.7):**
  - `Sidecar::parse(bytes, &Limits)` (BOM and CRLF accepted, a duplicate key takes the later value, the limits of `security.md` §4.2) → `Sidecar` or `ParseError` (the caller sets the file aside). `print()`: keys sorted by bytes at every level, two spaces, LF, final newline; `parse(print(x)) == x`.
  - `star(name) -> Field<bool>` (`Absent`, `Value`, `WrongType(value)`), `set_star(name, on)` (clearing removes the key, and the entry when it is empty; refuses to write over a wrong-type `photos` or entry), `photo_names()`, `version()`, `problems()` (wrong-type values as JSON pointers).
  - `plain_name(name)`: whether a key read from a sidecar may reach a file (`security.md` §5.4).
  - Everything not modelled is kept verbatim.
- **Public API (M6.8, `fields`):** every M6 key of `data-model.md` §3.
  - `photo(name) -> PhotoFields` (`star`, `caption`, `tags`, `hidden`, `edits`, `redo`, `date` as `Field`s; a date that does not parse is `WrongType`; the EXIF spelling is read) and `folder() -> FolderFields` (`description`, `date`, `place`, `hidden` under `"folder"`).
  - `set_photo(name, &PhotoValue)` and `set_folder(&FolderValue)`: one key at a time; the empty value (`false`, `""`, `[]`, `None`) removes the key, then the photo's entry or the `"folder"` object when it is left empty, and never creates anything; refused (`WrongType`) when `photos`, the entry or `"folder"` is not an object. `star`/`set_star` are the same for `star`.
  - `problems()` covers every M6 key; `fields::PHOTO_KEYS` and `fields::FOLDER_KEYS` name the keys read (the store's mapping test checks them against its tables).
  - No caps here: the store's `mapping` decides what the model takes (`dalica-store`).
- **Public API (M8.9, `fields` and `originals`):** `data-model.md` §3 and §6.
  - `saved_as(name) -> Field<SavedAs { name, recipe }>` and `set_saved_as(name, Option<&SavedAs>)` (writes `name` and `recipe` into the object already there, keeping its other keys; `None` removes the key and the emptied entry); `project() -> Field<String>` and `set_project(Option<&str>)` under `"folder"`. `fields::M8_PHOTO_KEYS` (`savedAs`) and `M8_FOLDER_KEYS` (`project`) sit beside the M6 tables, which are unchanged; `problems()` covers them. A `savedAs` name is read as written: whether it may reach a file is the reader's `plain_name` check.
  - `Originals` (`.dalica-originals/.dalica.json`): `parse(bytes, &Limits)` (as `Sidecar::parse`; the photo count applies to `"originals"`) → `Originals` or `ParseError` (the caller sets it aside), `print()`, `new()`, `version()`, `names()`, `entry(name) -> Field<Entry>`, `entries()` (only plain names with readable entries, in name order), `set(name, &Entry)` (merges into the entry, keeping unknown keys) and `remove(name)` (both `Refused::Name` for a name that is not plain, `Refused::WrongType` over a value that is not an object), `is_empty()`, `problems()` (wrong types, missing required keys, names that are not plain). `Entry { recipe, size, mtime (ms), width, height, digest, state: State::{Pending, Done}, time (ms) }`; `originals::{DIR_NAME, FILE_NAME, KEY, ENTRY_KEYS}`.
- **Public API (M9.6, `fields` and `albums`):** `data-model.md` §3 and §4. Per photo `photo_albums(name) -> Field<PhotoAlbums>` and `set_photo_albums(name, &members, managed)` (album id → position key; only the albums `managed` answers for are set or cleared, other memberships and unusable entries kept verbatim); per folder `folder_sort`/`set_folder_sort` and `folder_reverse`/`set_folder_reverse` in `"folder"`; at the top level `album_names() -> Field<AlbumNames>` and `set_album_names(&names)`. `fields::M9_PHOTO_KEYS`, `M9_FOLDER_KEYS`, `M9_TOP_KEYS`. M10.29 adds a photo's `changed` (`PhotoFields::changed`, `PhotoValue::Changed`, `fields::M10_PHOTO_KEYS`): a UTC time with milliseconds, written by `utc_text` and read by `parse_utc`; anything else is a value of the wrong type (`tests/fields.rs`). `AlbumsFile` (`albums.json`): `parse`, `print`, `new`, `version`, `albums() -> AlbumsRead { albums, bad }`, `ids`, `set(id, &Album)` (merging into the entry, unknown keys kept), `remove`, `problems`. Entries are moved between files by `dalica-store`'s `carry` (M9.9), which works on the parsed documents and keeps every key.
- **Public API (M13.2, `fields`):** `data-model.md` §3. Per photo `photo_faces(name) -> Field<PhotoFaces { faces, bad, over }>` and `set_photo_faces(name, &[Face])`; `Face { rect: FaceRect, person: FacePerson::{Unnamed, Ignored, Named(PersonId)} }`, written `{"rect": [x0, y0, x1, y1], "person"?: "<id>" | "ignored"}` (no `person` for an unnamed face). `geo(name) -> Field<GeoTag>` and `set_geo(name, Option<GeoTag>)` (`fields::GeoTag::{At(Geo), Removed}`), written `[lat, lon]`, or `null` for a location the user removed (M13.9: the file's GPS then no longer counts; no key says nothing). At the top level `people() -> Field<FolderPeople { people, bad }>` and `set_people(&BTreeMap<PersonId, PersonName { name, nickname }>)`. `FaceRect::new` (finite, inside `0..=1`, `x0 ≤ x1`, `y0 ≤ y1`) and `Geo::new` (latitude within ±90, longitude within ±180) keep six decimals, so a value prints as that decimal and reads back exactly. A face that is not usable (such a rectangle, a person that is neither a person id nor `ignored`) and the usable ones past `MAX_FACES` (256) are kept verbatim after Dalica's on a rewrite, and left out (`bad` positions, `over` count); a face is written into the entry it came from (the same rectangle first, then the leftover entries in order), so the keys of a face Dalica does not know stay with it. A `faces` that is not a list and a `geo` that is not a place are wrong types (`problems()`); clearing the faces keeps such a value, writing faces replaces it. People entries follow the album names' rules. `fields::M13_PHOTO_KEYS` (`faces`, `geo`), `M13_TOP_KEYS` (`people`), `IGNORED`, `MAX_FACES`.
- **Public API (M14.2, `legacy`):** `data-model.md` §9, `security.md` §4.2; read-only, written from public descriptions and black-box observation (provenance header in `src/legacy.rs`). The file names come from a masked byte constant: `sidecar_names()` (the current hidden name, then the older one), `originals_dir_name()`, `folder_section()`; never write them as literals. `LegacySidecar::parse(bytes, &LegacyLimits)` (file ≤ 64 MiB, line ≤ 1 MiB, ≤ 1 000 000 sections, ≤ 1 000 keys per section; past one → `LegacyError::{FileTooLarge, LineTooLong, TooManySections, TooManyKeys}`) reads `[section]` and `key=value` lines (split on the first `=`, LF or CRLF, no comments), merging repeated sections and keys (the later wins) and skipping lines outside a section or under an empty name; UTF-8 when an `[encoding]` section says `utf8=1` or a byte-order mark starts the file, Windows-1252 otherwise; `Text { text, lossy }` marks text with bytes that did not decode (U+FFFD; shown, never written). Typed reads: `folder()` (description, date from the day count, place, hidden category), `file_names()` and `file(name)` (exact, then ignoring case: star, hidden, caption, keywords, rotation, flip, crop, the edit and redo lists as raw tokens, the text overlay kept whole through its length prefixes with each block's text, text on/off, faces as rectangle + contact id padded to 16 digits or `Ignored`, album tokens, geotag), `albums()` (token, name, date in either form, description, place; tombstones without a name skipped), `contacts()` (the three-field form only), and `sections()`/`section(name)` for raw values. Rectangles: `decode_rect`/`decode_rect64` (padded to 16 digits, four 16-bit values over 65 535, `[x0, y0, x1, y1]` in the stored pixels). The originals folder's sidecar reads with the same `parse`.
- **Fuzz it:** `cd crates/sidecar/fuzz && cargo +nightly fuzz run legacy` (`docs/security.md` §7).
- **Test it alone:** `cargo test -p dalica-sidecar` (no window, GPU, network or personal photos needed): property tests for `parse(print(x)) == x` on random documents and any file name as a key, and for sidecars holding every M6 key with values of any type (reading never panics, a value set reads back exactly and every other key keeps its value). `tests/originals.rs` (M8.9): the record's documented key order, defaults and unknown keys, `../x` and `CON` kept but never offered, wrong types reported, damaged files refused, `savedAs` and `project` round trips; proptests for records under hostile names with values of any type, random bytes, and hostile `savedAs`/`project`. `tests/fields.rs` (M13.2): faces, people and geotags round-trip and print byte-stable, hostile faces, places and people kept and left out, unknown keys in a face kept, the face cap, and a proptest for any faces and place. `tests/legacy.rs` (M14.2, fixtures written from the documented format): every key of a sample folder, the originals folder's sidecar, the older encoding's accented names, values holding `;` and `=` and a text overlay holding a line break, short and full rectangles, duplicated, reversed and empty sections, each limit refused by name, and proptests for random bytes and line soups. The integration tests are one binary (`tests/all.rs`, one module per file: `cargo test -p dalica-sidecar --test all <file>::` runs one); a task's gate runs them quick, `DALICA_FULL_TESTS=1` at full strength (every property case, every size).
