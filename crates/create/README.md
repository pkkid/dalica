# dalica-create

**Layer L3.** Export (resize, quality, watermark, metadata copy), collage layout and render, slideshow sequencing.

- **May depend on:** L0–L2 (`docs/architecture.md` §2; `cargo xtask layers` enforces it). Uses `core` (the name sanitizer), `fs` (export reads sources and writes new files and folders that never replace one; the output pipeline itself never touches the disk), `image` (decode, colour stage, resize, the M8.6 encoders), `edit` (the recipe and its CPU renderer), `meta` (metadata carried to a new file, M8.7; the orientation tag and the owned fields of a lossless Save), `sidecar` (the originals record `.dalica-originals/.dalica.json`, M8.9). External: `moxcms` (the sRGB profile), `ab_glyph` (the watermark's text, Inter SemiBold), `md5` (the originals' `md5:` digests), `thiserror`. Tests also use `dalica-scenes`, `tempfile`, `proptest` and `zune-jpeg` (the decoder's YCbCr samples, to check a lossless rotation within 1 level).
- **Public API (M8.10):**
  - `output::render(source bytes, &recipe, &Spec) -> Result<Output>`: the one output pipeline Save, Save a Copy, Save As and Export share (`architecture.md` §6, `data-model.md` §6). The source is read at full size under the decode limits (header checked before any decoder, the decoder panic-guarded), the recipe rendered at full size with the EXIF orientation applied (`edit::render`), fitted to `Spec::long_side` without ever enlarging (`image::resize::fit`), passed through the watermark hook, encoded (JPEG at `Quality::Match` = the source's estimate and chroma subsampling, else 90 and 4:4:4, or `Quality::Fixed(1–100)`, transparent pixels over white; PNG keeping transparency and 16 bits; grey stays grey while every pixel is neutral; an sRGB profile only when the source had one), then the source's EXIF, XMP and IPTC carried with orientation 1, the new size, an optional fresh 160-pixel EXIF thumbnail, GPS removed on request, and the caller's owned fields merged under its `WriteOptions`. A 16-bit grey or RGB PNG without a profile whose recipe only rotates and flips (no resize, no watermark) keeps its samples exactly; any other edit renders at 8 bits and is widened back to 16. Sources whose metadata `meta` does not read (GIF, BMP, HEIF, JPEG XL, PSD, non-TIFF raws) get only those facts and the owned fields (`Report::source_metadata`). Pure: bytes in, bytes out, nothing on disk.
  - `output::target(format, transparent, Purpose)`: `InPlace` (JPEG → JPEG, PNG without transparency → PNG, anything else `None`: the Save goes beside), `Beside` and `Copy` (JPEG), `Export` (PNG for transparency, else JPEG); `Choice::For(purpose)` or `Choice::Exactly(format)` (Save As).
  - `Spec` (`Spec::new(purpose)`: full size, Match, no thumbnail, watermark or owned fields), `Quality`, `Report` (format, size, bits, channels, quality and subsampling written, the source's estimate, profile, thumbnail, `source_metadata`, what was dropped), `Error` (`Spec`, `NotInPlace`, `Decode`, `Render`, `Encode`, `Metadata`, `OutOfMemory`, `Profile`; `reason()` is the text shown).
  - `watermark::draw(&mut Rgba8, text)` (M8.11): the export watermark the pipeline draws after resizing, white text with a soft shadow bottom-right, 3 % of the long side high (`SIZE`, `MARGIN`), cleaned and shrunk to fit (`clean`, `layout`), left out rather than failing when it cannot be drawn; ported from LightCraft.
- **Public API (M8.13), `export`** (`creating.md` §2):
  - `ExportOptions` (`Size::Original` or `Size::LongSide(100–4000)`; `QualityPreset` Automatic = Match, Normal 85, Maximum 95, Minimum 60, Custom 1–100; `numbers`; `watermark`; `remove_location`), `check()` and `spec()` (the `output::Spec` of an export: no EXIF thumbnail, every owned field written, stars as ratings too).
  - `plan(location, folder_name, fallback, items, &options) -> Result<Plan>`: the location made when missing, the export folder under a free sanitized name (`fs::create::new_folder`: `<name>-001` when taken), and `names(items, numbers)`: each photo's sanitized stem, `001-` numbered in tray order when asked (more digits past 999), fitted to 255 bytes with its extension; videos (`Kind::Video`) skipped until M15. `Item` (path, kind, recipe, owned `Changes`), `Planned`, `Skipped`, `Destination` (folder, name, spec).
  - `export_one(&Planned, &Destination, cancelled: &dyn Fn() -> bool) -> Outcome`: the source read under `MAX_FILE` (1 GiB), rendered through `output::render`, written as `<stem>.jpg` (`.png` for transparency) through `fs::create::new_file` (`-001` on a taken name, never replacing a file). `Outcome::Written` (path, name, report), `Skipped` (not a picture, too large), `Failed` (gone, unreadable, not written), `Cancelled` (asked before the read, the render and the write; nothing partial is ever left). `run(&Plan, cancelled) -> Summary` does a whole plan on the calling thread.
- **Public API (M8.12, M8.14), `save`** (`data-model.md` §6, §10.9; call on a worker, every disk step through `dalica-fs`):
  - `save::save(folder, name, &recipe, &changes, &Options) -> Result<Saving>`: the dispatch Save calls. A JPEG whose whole recipe only rotates and flips goes lossless (`save::lossless`); a format that cannot be written in place goes beside (`save::beside`); anything else `save::in_place`. `Saving::InPlace(Saved)` (the record entry, the saved file's identity, the `Report`, whether the original moved) or `Saving::Beside(Beside)` (the new JPEG's name and the recipe it holds: the photo's `savedAs`).
  - `save::in_place`: refuse an unrenderable recipe; read the photo and its identity (`Options::seen` refuses a file changed since the library read it); render through `output::render` at Match quality with a fresh EXIF thumbnail and the owned fields under the write-back options (from the kept original with the recorded recipe first, for a photo saved before); the record entry written `pending`; the original moved into `.dalica-originals/` (first Save) or checked; the new file committed and verified; the entry marked `done`. `save::undo` (Undo Save: the recorded recipe back) and `save::revert` (Revert: none) move the kept original back and drop the entry. `digest`, `renders`, `check_recipe`, `Error` (`reason()` is the text shown).
  - `save::lossless` (M8.14): `turn(source, &recipe, &changes, &Options) -> Option<Turned>` turns a JPEG in the DCT domain (`image::jpeg_transform`, the file's own quantisation tables, orientation set to 1, the EXIF thumbnail turned in its own span) or, when that is not lossless here (partial MCUs on a moved edge, progressive, 12-bit, data after the end of the image) or the net transform is the identity, keeps the pixel bytes and writes the composed orientation (`meta::carry::set_orientation`); `Method` says which. Both go through the same journal as a rendered Save.
  - `save::beside` (M8.14): renders a JPEG `<stem>.jpg` (or the next free `-001`) beside a PNG with transparency, TIFF, WebP, GIF, BMP, HEIF, JPEG XL, PSD or raw through `fs::create::new_file`, the source and its originals record untouched.
  - `save::copy::copy(folder, name, &recipe, &changes, &Destination, &Options) -> Copied` (M8.14): Save a Copy (`Destination::Numbered`: `<stem>-001.jpg`, the next free number) and Save As (`Destination::Path { path, format }`: JPEG or PNG; an existing path refused), every owned field written, never replacing a file.
- **Test it alone:** `cargo test -p dalica-create` (no window, GPU, network or personal photos needed). `tests/output.rs` (helpers in `tests/common/`: scenes as JPEG, 8/16-bit PNG and alpha files, decoding, the `edit::render` oracle, PSNR, fingerprints): a q75 JPEG re-encoded at Match estimates at 75 ± 2 within 40 dB and a mean of 1 level; 4:2:0 kept; rotations give orientation 1 and the turned size; resizes hit the long side exactly and never enlarge; alpha and 16 bits kept (16-bit samples bit-exact when only moved); EXIF, XMP and IPTC carried with the owned fields and a thumbnail; GPS removed when asked; an sRGB profile only after a tagged source; a PNG output decodes to exactly `edit::render`, a JPEG one within 40 dB, both fingerprinted (`tests/fingerprints/output-*.json`; PNGs in `target/test-output/create/`, `DALICA_BLESS=1` rewrites them); undecodable, truncated and oversized sources and bad requests are `Err`; a 24 MP save is timed. `tests/export.rs` (temporary folders): exported files decoded and checked (long side, never enlarged, each preset's quality estimate ± 2, metadata and owned fields copied, GPS removed only when asked, edits rendered), a PNG with alpha stays PNG, collisions `-001`, numbers in tray order, the folder's free and sanitized name, videos and undecodable files skipped, a cancel at every step leaving only complete files, and a proptest that every planned name is a plain file name. `tests/save.rs` (temporary folders): Save → Undo Save → Save → Revert gives the exact original bytes; a second Save keeps the first original and renders from it; quality, orientation 1 and metadata carried; changed photos, links, mismatched backups, read-only folders and unknown operations refused with nothing moved. `tests/save_lossless.rs`: a rotated MCU-sized JPEG keeps its own (transposed) tables and decodes within 1 level of the rotated original with a turned thumbnail and only that changed in EXIF; a half turn copies the tables byte for byte; partial-MCU sizes, data after the end and a cancelling recipe keep their pixel data bytes with the composed orientation (an EXIF block added when there is none); a flip after a rotation; Undo Save and a later Save from the kept original; owned fields merged; a damaged file refused; a 24 MP quarter turn timed. `tests/save_beside.rs`: a PNG with alpha, a TIFF, a WebP and a raw each get a JPEG beside and stay byte-identical, transparency over white, a taken name moves to `-001`; copies take the next free number with every owned field; Save As writes the chosen path and format and refuses an existing path; bad copies are refused with nothing written.
