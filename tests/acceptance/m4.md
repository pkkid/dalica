# M4 manual check: scroll with the speed thumb and tune its curve

`cargo xtask accept M4` checks the rest headlessly: the live app on the demo library (tree rows and
order, a row click, collapsing Folders, keyboard stops at section edges, the tray scenario with one
undo step, the status-line cases, whole-window screenshots at both sizes), the thumb held at its top
speed through an index-only 100 k-photo library without a placeholder on any frame, every M4 crate
suite, and the benchmarks' counters in a debug build. It prints where the two screenshots are
(`target/test-output/acceptance/m4-1400x900.png` and `m4-900x600.png`): look at them first, beside
`docs/ui-layout.md` §4–§6.

The frame-time budgets need a release build, so they run only when asked for (a few minutes the
first time for the release build, then about 35 s more than the debug run):

```sh
DALICA_ACCEPT_RELEASE=1 cargo xtask accept M4
```

It adds `library_bench` in full (the 100 k scroll's p95 UI time ≤ 8 ms, cells visited flat from
10 k to 100 k), the thumb test in release (p95 ≤ 8 ms) and the pack bench at 100 000 entries
(packed against loose reads, printed).

What only a person can judge is how the **speed thumb** feels (`docs/ui-layout.md` §5.6): the
thumb sets a speed, not a position, and its curve is tuned by feel at this review. This needs a
display and a mouse or a touchpad.

## 1. The demo library (60 photos)

1. Start the app on the demo library:

   ```sh
   cargo run --release -p dalica -- --demo
   ```

2. Press the thumb (the 16 × 64 bar at the centre of the scroll bar, right of the photos) and pull
   it down a little: the photos scroll down slowly; the further you pull, the faster they go.
   Within 4 points of the centre nothing moves. Pull it up: the same, upward.
3. Let go: the view stops at once where it is and the thumb glides back to the centre (150 ms).
   The faint short line in the track (the position marker) shows where you are in the library;
   it cannot be dragged.
4. Try the other ways to move: ⇑ / ⇓ (top and bottom pairs of the scroll bar) bring the previous /
   next folder's header to the top; ▲ / ▼ move a row; a click in the track pages; Page Up / Page
   Down, Ctrl+↑ / Ctrl+↓ and Ctrl+Home / Ctrl+End (Cmd on macOS) do the same from the keyboard;
   a click on a folder in the tree eases its header to the top.

Sixty photos are only three screens, so at the top speed the demo is crossed in a blink: use it for
the slow end of the curve and the feel of the release, and the large library below for the rest.

## 2. A large library (20 000 photos in 200 folders)

1. Make it once, in a new folder of your choice (an absolute path; some 15 s and 300 MB):

   ```sh
   DALICA_M4_LIBRARY=/tmp/dalica-m4 cargo test --release -p dalica-acceptance --test m4 -- --ignored --exact make_the_large_demo_library --nocapture
   ```

   It prints the command that opens it, with the thumbnail cache it made beside it:

   ```sh
   DALICA_CACHE_DIR=/tmp/dalica-m4/cache cargo run --release -p dalica -- --library /tmp/dalica-m4/library
   ```

2. Hold the thumb at the end of the track: the light table runs at the top speed, 40 screen
   heights a second, through 200 folders. Every cell shows something on the frame it appears
   (its colour sketch while the thumbnail loads, never a grey box), and the scrolling stays smooth.
   Let go somewhere in the middle: the thumbnails sharpen within a moment.
3. Hold it at a third and at two thirds of the way: is there a usable speed for browsing (reading
   the folder titles as they pass) and one for crossing the library? Is the dead zone too small or
   too large?

## 3. Tuning the curve

The curve is `top · u^exponent` screen heights a second, `u` the share of the way from the dead zone
to the end of the track. Both numbers are read from the library's `settings.json` when the app
starts, so they can be changed without a rebuild:

```json
"scrolling": {"thumbExponent": 2, "thumbTopSpeed": 40}
```

- `thumbExponent` 0.25–8 (1 linear, 2 quadratic, the default; higher keeps the middle of the track
  slower and the end as fast);
- `thumbTopSpeed` 0.5–400 screen heights a second at the end of the track (default 40).

A value outside its range is taken as the default.

1. Quit the app (it writes `settings.json` while it runs and when it closes, so edit the file only
   while the app is not running).
2. Open the library's `settings.json`: for the large library `/tmp/dalica-m4/library/settings.json`;
   for the demo `dalica-demo/library/settings.json` in the OS temp folder (`/tmp` on Linux,
   `$TMPDIR` on macOS, `%TEMP%` on Windows). Add or change the `"scrolling"` object at the top
   level, keeping the other keys as they are.
3. Start the app again with the same command and try the thumb. Some pairs to compare: `2 / 40`
   (the start), `1.5 / 30`, `3 / 60`, `2 / 20`.

Write the pair you like (or what felt wrong) on the M4.R check-in: it becomes the default. Delete
`/tmp/dalica-m4` when you are done.
