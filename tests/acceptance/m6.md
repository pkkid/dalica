# M6 manual checks: photo info in the app, a tag in another application, and an installed package

`cargo xtask accept M6` checks the rest headlessly. The live app (`dalica --headless`, driven over
its control channel) on a fresh library: nine JPEGs of one picture stored with EXIF orientations
1–8 are rotated and flipped by the commands, each turned photo takes the displayed shape, and
photos whose turns add up to the same transform show the same pixels whatever their EXIF
orientation; one undo and redo; a photo and a folder hidden; captions, tags with partial counts,
quick tags, a date set and a date shifted, a folder's description, place and date; every M6
command registered and live, refusing hostile params without changing anything; each M6 dialog
opened and cancelled. The captions, tags and dates reach the JPEG files (read back by `dalica-meta`,
and by `exiv2` when it is installed) with their pixels untouched, and `photo.metadata` reports them.
Then the app quits, the index is deleted, the app rebuilds the library from the sidecars, and every
field is back: hide, captions, tags, dates, rotations and folder info, with the window exactly as
before. After that: the M6 crate suites (every command's contract, `xmp-interop.md` §8 tests 1–4 and
6–10), `panic_hunt`, the metadata corpus when `corpus/metadata/` is here and verified (it says so
plainly when not), and the latest Release dry run read through `gh` (built and checksums verified on
Linux, Windows and macOS; it says which run, and says so plainly when `gh` cannot answer).

It prints where the screenshots are: look at them first, beside `docs/ui-layout.md` §5:

- `target/test-output/acceptance/m6-1400x900-cells.png`: the nine cells, two portrait (a quarter
  turn), the others landscape, the white corner mark of each picture where its turn puts it;
- `m6-1400x900.png`: captions under their cells, the header's description and "· Lisbon";
- `m6-900x600.png`: View ▸ Hidden Pictures: the hidden photo at 40 %, the Hidden Folders group;
- `m6-1400x900-rebuilt.png`: the same window after the rebuild.

What only a person can judge is how it feels with real photos, what another application makes of
the tags, and installing the preview. These need a display.

## 1. Rotate, hide and caption photos in the app

Use a copy of a folder of your own photos (Dalica writes captions, tags and dates into the files
themselves, by default), on a new library:

```sh
cargo run --release -p dalica -- --library /tmp/dalica-m6/library
```

1. Add the folder (File ▸ Add Folder…). Select a landscape photo and press Ctrl+R: its cell turns
   portrait at once, with no flash and no wait. Ctrl+Shift+R turns it back; the bottom bar's two
   rotate buttons do the same for the selection. Picture ▸ Flip Horizontal (Ctrl+Shift+H) mirrors
   it. Ctrl+Z undoes each step.
2. Picture ▸ Hide: the photo leaves the light table and Ctrl+A skips it. View ▸ Hidden Pictures
   shows it again, dimmed; Picture ▸ Unhide brings it back. Folder ▸ Hide moves a folder to the
   Hidden Folders group, shown only with Hidden Pictures.
3. Picture ▸ Edit Caption: type a caption under the cell, Enter. View ▸ Thumbnail Caption ▸
   Caption shows it under the cell. Typing Ctrl+8 in the editor stars nothing.
4. Click the folder header's "Add a description" line and type one; double-click the folder's title
   for Folder Properties (date, place, description).
5. Tools ▸ Adjust Date and Time… on a few photos: shift them by an hour and see the order change.
6. Alt+Enter: the Properties pane follows the selection (camera, exposure, caption, tags);
   [Show All Metadata] lists every field.
7. Help ▸ Rebuild Library…, confirm: everything above is still there.

## 2. Tag a photo and see the tag in another photo application

1. Ctrl+T opens the Tags pane. With two or three photos selected, add a tag such as `m6-check`
   (Enter); the list shows its partial count ("m6-check (2 of 3)").
2. Within a few seconds the tag is in the files. Open one of them in another photo application:
   digiKam (Tags), darktable (tagging module), Adobe Lightroom or Bridge (Keywords), Windows
   File Explorer (Properties ▸ Details ▸ Tags), or from a terminal `exiv2 -px FILE` or
   `exiftool -Subject -Keywords FILE`. The tag is there, and the caption as the description.
3. Change the tag in the other application and save: back in Dalica (still running), the change
   arrives as one step you can undo.

## 3. Install a package and browse your own photos

The latest Release dry run's artifacts (the run `accept M6` printed, or the newest one under
Actions ▸ Release) are unsigned previews. Download your platform's and its checksums:

```sh
gh run download <run id> -n release-linux-x86_64 -n sha256sums   # or release-windows-x64, release-macos-universal
sha256sum -c --ignore-missing SHA256SUMS.txt
```

- **Linux:** install the `.deb` (`sudo apt install ./dalica-0.1.0-linux-x86_64.deb`) or `.rpm`, or
  run the `.AppImage` (`chmod +x`, then run it), or `flatpak install --user dalica-…flatpak`.
- **Windows:** run the `.msi` (SmartScreen warns about an unsigned installer: More info ▸ Run
  anyway), or unzip the portable zip and run `dalica.exe` (its data stays beside it).
- **macOS:** open the `.dmg` and drag Dalica to Applications; the first start needs right-click ▸
  Open (the app is signed ad hoc only).

Start it from the menu or launcher, let the first-run panel add your Pictures folder (or choose
folders), and browse: thumbnails fill in, scrolling stays smooth, Help ▸ About Dalica shows 0.1.0
with its commit and build date, Help ▸ Release Notes shows the 0.1 notes. Uninstall it the
platform's usual way afterwards.

Write what felt wrong on the M6.R check-in. Delete `/tmp/dalica-m6` when you are done.
