# M15 manual checks: real clips and sound, a screen reader, an input method, the system's own programs, a real camera, the Thai review, the signed packages

`cargo xtask accept M15` checks the rest headlessly. The live app (`dalica --headless`, driven over
its control channel) on a folder of two photos and three H.264 clips made by the test (an MP4, a MOV
and a Matroska file of 2 s with silent sound) and a folder of an MPEG-4 Part 2 clip, an HEVC clip
and a hostile container: the three list as videos of 2 s and their cells show their posters (the
first frame that is not black, told by its grey); the hostile container lists with no duration and
its reason, without a panic; the Videos filter leaves only videos; Export writes each playable
clip's poster frame and counts the clip it cannot play, skipped with the reason; a slideshow counts
a clip and plays it to its end (2 s against a display time of 1 s); in the edit view the player
plays and pauses, `.` steps a frame, Set End and Set Start trim at the playhead and the readout says
so, Save Frame as Picture writes the frame shown into `Pictures/Dalica/Video Frames`, which the
library lists; the MPEG-4 Part 2 clip and (in a build without the `hevc` feature) the HEVC one say
"This video can't be played" with Open With beside it and Play greyed; after a restart the trim is
still there. On a library of five photos: Options ▸ General ▸ Language switches between English and
Thai without a restart in the library, the edit view and the Options dialog, keeping the view, the
photo, the selection and the undo history (Undo in Thai takes back a star given in English); the
search banner reads right for 0, 1, 2 and 5 pictures in each language; at 900 × 600 the menu bar
stays inside the window; in the pseudo-locale every label but user data is bracketed; F10 and the
arrows walk the menu bar, and Tab walks the Options dialog's controls without leaving it. Over
automation (even with `--automation-allow-external`) Locate on Disk, Open With and Open in External
Editor are refused and a headless app has no clipboard; in process, with the recording `Os`
standing for the system, a person's Ctrl+Enter, folder icon, Ctrl+Shift+O, Open With ▸, Copy Path
and Ctrl+C hand it the right files. A second `dalica --view FILE` hands FILE to the running Dalica
and exits 0. The in-memory PTP camera's five pictures import through the Import room byte for byte
with the camera's dates as their times. W17 through `dalica-cli mcp` over real stdio. After that:
M15's crate suites (the AccessKit audit of every view and dialog, the keyboard walk, the catalogs'
cut-and-wrap sweeps at both sizes among them), HEVC with its feature, `cargo xtask i18n`, the
workflow pass rate (`cargo xtask stats --check`, the floor of 17), `cargo xtask parity` in its
review form, the SBOMs, `panic_hunt`, and the `video_probe`, `video_play`, `camera_import`,
`a11y_frame` and `i18n_frame` benches in a debug build (times printed). With
`DALICA_ACCEPT_RELEASE=1` it runs them in release with `--check`, each within its budget.

The release dry run (every Windows and macOS artifact signed with a throwaway identity, the
signature checks passing) is the Release workflow's on a pull request that touches `packaging/` or
the workflows, or a manual run on any branch other than a release tag; look at its last run's jobs.

It prints where the screenshots are: look at them first, beside `docs/ui-layout.md` §5,
`docs/editing.md` §11, `docs/localization.md` and `docs/design-system.md` (all in
`target/test-output/acceptance/`, at 1400 × 900):

- `m15-1400x900-library-videos.png` (and `-masked`): Clips with three grey video cells (the
  sprocket edge, the 0:02 pill) beside a red and a blue photo; Old with two video tiles (the play
  sign, 0:02) and the hostile container's tile with no duration;
- `m15-1400x900-player.png`: the edit view on `clip.mp4` paused at 0.4 s, the video tab (Save
  Frame as Picture, Export Clip, the rotations), the trim ruler's handles at 0.4 s and 1.04 s, the
  readout "(trimmed to …)", Undo Trim live;
- `m15-1400x900-library-en.png` and, built with `CRAFT_FONTS_DIR`, `m15-1400x900-library-th.png`:
  the same library in English and in Thai (the menu bar, the toolbar, the folder's date, the bottom
  bar), nothing cut, the photos' names left as they are.

What only a person can judge needs real hardware, real programs and a fluent reader. Work in a
release build (with the fallback faces: `CRAFT_FONTS_DIR` pointing at craft-fonts at its pin), on
each OS, on a new library holding a few photos and clips of your own:

```sh
CRAFT_FONTS_DIR=… cargo build --release -p dalica
target/release/dalica --library /tmp/dalica-m15/library
```

## 1. Real clips, real sound

1. Add a folder with clips from a phone (an iPhone's `.MOV`, an Android `.mp4`) and a camera. Each
   shows as a video cell with its duration and its poster; the Videos filter leaves only them.
2. Open one: it plays with sound at its rate, the scrubber and its readout follow, `,` and `.`
   step a frame, Space pauses, Full Screen fills the screen. A portrait clip stands upright.
3. Trim it with the handles and with Set Start and Set End; quit and start again: the trim is
   there. Export Clip writes the trimmed part, which another player opens.
4. Save Frame as Picture: the picture in Video Frames is the frame shown, sharp, at the clip's
   size.
5. A slideshow of photos and clips with music on (Options ▸ Slideshow ▸ Play music, a folder of
   your own music): the music plays, each clip plays to its end, muted unless Play video sound.
6. In a build with `--features dalica-image/hevc`, an iPhone HEVC clip plays as above; in a
   default build it shows "This video can't be played (HEVC support isn't included in this
   build)" with Open With.

## 2. A screen reader on each OS

With Orca (Linux), Narrator or NVDA (Windows) and VoiceOver (macOS):

1. Walk the library with Tab and the arrows: the tree's rows say their names, levels and counts;
   the light table's cells say their names and whether they are selected; the toolbar's buttons
   and the filters say what they do.
2. Open Options (Ctrl+,): the dialog is announced with its title; every tab, checkbox, slider (with
   its value) and button has a name; Esc closes it.
3. In the edit view on a clip: the player's buttons, the scrubber with its time and the volume
   are named.
4. Switch to Thai and walk the library again: the names are read in Thai (a few English words left
   over is a bug: note which).

## 3. An input method

1. With an input method on (Thai Kedmanee; a Japanese or Chinese IME), type a caption and a tag:
   the text composes in place, the candidate window sits by the field, and what is committed is
   what was chosen.
2. Rename a photo and a folder with it.

## 4. The system's own programs

1. Locate on Disk (Ctrl+Enter, the photo menu, the folder header's icon): the file manager opens
   with the photo or folder selected.
2. Open With ▸ lists the applications the system offers for the type (Dalica left out); choosing
   one opens the photo in it.
3. Options ▸ General ▸ External editor: Browse… to an editor; Ctrl+Shift+O opens the selected
   photos in it.
4. Copy (Ctrl+C) three photos and paste them in the file manager: three files arrive. Copy Path
   and paste into a text editor: the path. Copy a photo as a picture and paste it into an image
   editor or a chat window.
5. Drag three photos out of the light table onto the file manager, a mail draft and a chat window:
   each takes the files; a photo with unsaved edits says "Unsaved edits stay in Dalica".

## 5. Dalica as the default viewer

1. Options ▸ Photo Viewer ▸ File Types (and the question after the first run): choose JPEG and PNG.
   On Windows the system's Default apps opens where it must; on macOS follow the answer's steps in
   Finder.
2. Double-click a JPEG in the file manager: Dalica's viewer opens it. With Dalica already running,
   double-click another: the running Dalica shows it, no second window starts.
3. "Don't use Dalica as a viewer": the previous viewer opens the file again.

## 6. A real camera or phone

1. Plug in a camera (PTP) and a phone (MTP, unlocked, file transfer allowed). Ctrl+M: Import from:
   lists each by name; a camera another program holds is greyed with the reason.
2. Choose one: its pictures fill the tray with the camera's own thumbnails, quickly.
3. Import All into a dated folder: every file arrives, its time the camera's; importing again finds
   them all already in the library. "Delete copied files" asks first, then removes only those.

## 7. The Thai review

1. The maintainer's wife reads the Thai catalog (`crates/ui/src/i18n/th.tsv`; every entry is still
   a `~` draft) in the running app: the library, every menu, the edit view, Options and the common
   dialogs, against `docs/localization-th.md`. Wrong or awkward wording is fixed in the catalog and
   the `~` dropped from each entry she approves.
2. Long Thai labels wrap only between words, and nothing is cut at 900 × 600.

## 8. The signed packages

1. Install the release's signed MSI (and run the portable `.exe`) on a clean Windows: no
   SmartScreen or "unknown publisher" warning; the publisher is Dalica's certificate.
2. Install the notarized DMG on a clean Mac: Gatekeeper opens it without a warning
   (`spctl -a -vv Dalica.app` says "Notarized Developer ID"); the CLI zip's `dalica-cli` runs
   without a quarantine prompt.
3. `sha256sum -c SHA256SUMS.txt` passes for every file of the release; each package's SBOM is
   attached beside it.
