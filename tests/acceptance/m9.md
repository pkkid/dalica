# M9 manual checks: albums, search and file operations on your own photos

`cargo xtask accept M9` checks the rest headlessly. The live app (`dalica --headless`, driven over
its control channel) on fresh libraries: an album over three folders in a custom order and every
album command (create, properties, add, reorder, remove, cover, Sort Album By, Reverse Order,
delete), each undone and redone, a reorder by dragging in the album, and the album's order kept
after `albums.json` and the index are deleted and the library rebuilt (`data-model.md` §10.12).
The search grammar over 27 queries, the filters and the age, search mode from `search.set` and
from the toolbar's field with the banner's text and counts checked against the files on disk,
Save Search as Album, Show All and Find Duplicates. Photos moved with their stars, captions, tags,
recipes, album places and kept originals (§10.3), through the window too (the drag pill, the
first-time question, "Don't ask again", Ctrl+Z); copies and the collision question; Move to New
Folder; Rename Files from F2; a folder renamed and moved; Delete from Disk to the trash and back;
a folder deleted with its other files; hard names through all of it (§10.7); a folder moved
outside Dalica while it watches and between two sessions (§10.2); and a move across two file
systems that copies, verifies and only then trashes the source (between the temporary folder and
`/dev/shm` on Linux; elsewhere the engine with that path forced). Each with its undo. After that:
M9's crate suites, `panic_hunt`, and the `search` bench on 2 000 photos in a debug build (times
printed). With `DALICA_ACCEPT_RELEASE=1` it also runs the bench over the synthetic 100 k library
in release and asserts the budgets: index build ≤ 630 ms, one word ≤ 1.7 ms, three words and a
filter ≤ 0.6 ms, a `-word` ≤ 5.1 ms, `search.set` to applied ≤ 22.3 ms (medians).

What only a person can judge is whether organising feels safe and quick on real photos. These need
a display and a copy of a few folders of your own photos. Work on the copy, on a new library, in a
release build:

```sh
cargo run --release -p dalica -- --library /tmp/dalica-m9/library
```

Add the copied folders (File ▸ Add Folder…) and wait for the thumbnails.

## 1. An album from three folders

1. Put photos from three different folders in the tray (click, Ctrl-click; Hold keeps them), then
   File ▸ New Album… (Ctrl+N). Name it, tick "Use the date of the newest photo", OK. The album
   appears in the tree's Albums group with its count, selected, and its section shows the photos.
2. Drag photos within the album's section: the blue insertion bar shows where each lands. Put the
   last one first. Album ▸ Sort Album By ▸ Name, then Edit ▸ Undo: your order comes back.
3. Right-click a photo in the album: Set as Album Cover; the tree row's thumbnail follows. Remove
   from Album asks first and leaves the file where it was.
4. Quit and start again: the album and its order are as you left them. Album ▸ Delete Album…, then
   Edit ▸ Undo: the album is back with its order.

## 2. Search your own photos

1. Click the search field (Ctrl+F) and type a word from a folder name, a caption or a tag: the
   light table narrows as you type, the blue banner says how many pictures in how many folders,
   how long it took and how many bytes. Does it feel instant on your whole library?
2. Type `tag:` and pick a tag from the suggestions with the arrow keys and Enter.
3. Try the Starred, Video and Geotagged toggles and the age slider ("Pictures up to 3 months
   old") with and without text. Faces is greyed with its reason.
4. Click Show All: every folder is back and the light table is where you left it.
5. Tools ▸ Experimental ▸ Show Duplicate Files: copies of the same file are grouped side by side
   under "N duplicate groups (M files)"; nothing else is grouped.

## 3. Drag photos onto a folder, and undo

1. Drag a photo from the light table onto another folder in the tree. The pill near the pointer
   says "Move 1 photo to <folder>" and the row lights up. Drop: the first time Dalica asks; tick
   Don't ask again and Move. In your file manager the file has moved, and its star, caption and
   tags are still on it in Dalica.
2. Edit ▸ Undo: the file is back where it was, in your file manager too.
3. Hold Ctrl while dropping: the pill shows a +, Dalica asks "Copy 1 file to …?", and the copy
   appears beside the original's data. Edit ▸ Undo sends the copy to the trash.
4. Drag a photo onto a folder that already holds a file of that name: Rename Duplicates gives
   `<name>-001`; Skip Duplicates leaves both untouched.

## 4. Rename a batch

1. Select a few photos and press F2. Type a name: the example line follows the typing and the
   "Add the date taken" and "Add the image size" boxes. Rename: the files are `<name>-001` … in
   the light table's order, on disk too.
2. Edit ▸ Undo: the old names, on disk too.

## 5. Delete to the trash and restore it

1. Select a photo and press Delete (Ctrl+Delete in an album): "Move the selected picture to the
   trash?". Move to Trash: the photo leaves Dalica and appears in your system's trash.
2. Edit ▸ Undo (Linux, Windows): the photo is back where it was with its star and caption. On
   macOS Undo is greyed and says to restore it from the Trash: do that in the Finder, and Dalica
   finds it again.

test files) when you are done.
